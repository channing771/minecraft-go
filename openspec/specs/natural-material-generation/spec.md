# natural-material-generation Specification

## Purpose

为新生成区块提供可复现、连续的沙子、砾石、黏土和雪块，并让旧世界能在完整备份保护下离线、可恢复地采用同一自然材料规则，而不改变既有存档或网络版本。

## Requirements

### Requirement: 四种自然材料的确定性连续生成
系统 SHALL 仅由世界种子和方块坐标确定沙子、砾石、黏土和雪块的自然生成结果，不得依赖生成、查询或区块加载顺序。相同种子和坐标 MUST 始终返回相同结果；生成结果 MUST 在区块边界与负坐标连续，且同类自然材料在固定种子样本中形成相邻区域而非逐格棋盘噪声。

#### Scenario: 单点查询与整区块生成一致
- **GIVEN** 固定世界种子和任意区块坐标
- **WHEN** 系统逐点查询该区块全部方块并生成完整区块
- **THEN** 每个方块坐标的两种结果 MUST 完全相同

#### Scenario: 负坐标和区块边界保持连续
- **GIVEN** 固定世界种子以及跨越正负坐标的相邻方块或区块边界
- **WHEN** 系统分别查询边界两侧的自然材料结果
- **THEN** 结果 MUST 仅由连续世界坐标决定，不得因区块归属或坐标符号产生接缝

#### Scenario: 四种材料均可在固定样本中出现
- **GIVEN** 固定种子和覆盖正负坐标的大范围固定样本
- **WHEN** 系统查询该样本的地表和指定浅层位置
- **THEN** 沙子、砾石、黏土和雪块 MUST 各至少出现一次，且每种 MUST 至少有一对水平相邻方块

### Requirement: 矿石只替换最终石头
系统 SHALL 在所有自然材料规则完成后才应用既有煤矿和铁矿判断。煤矿和铁矿 MUST 仅替换最终结果为石头的方块，并保持既有高度上限、概率、salt 和铁矿优先级。

#### Scenario: 自然材料不被矿石替换
- **GIVEN** 某方块坐标的自然材料结果为沙子、砾石、黏土或雪块
- **WHEN** 该坐标同时满足既有煤矿或铁矿选中条件
- **THEN** 结果 MUST 保持该自然材料，不得生成矿石

### Requirement: 离线迁移与服务器启动互斥
系统 SHALL 提供 `mcgod --world <世界目录> --migrate-materials --backup <备份目录>` 离线迁移入口。`--backup` MUST 必填；迁移模式 MUST 获取既有世界锁、不得监听 TCP 或启动服务器，并在世界正在使用、备份目录位于源世界内部或备份目录不能安全识别时失败。

#### Scenario: 迁移模式不启动服务端
- **GIVEN** 用户提供有效世界目录、`--migrate-materials` 和外部 `--backup` 目录
- **WHEN** `mcgod` 执行迁移模式
- **THEN** 它 MUST 在持有世界锁期间完成迁移，且 MUST NOT 监听 TCP 或进入服务端运行循环

#### Scenario: 被占用世界拒绝迁移
- **GIVEN** 目标世界已被服务器或客户端持有既有世界锁
- **WHEN** 用户执行迁移模式
- **THEN** 命令 MUST 失败，且 MUST NOT 修改源世界或写入完成状态

### Requirement: 迁移先创建可验证的完整备份
系统 MUST 在首次修改源世界前创建并同步完整备份。备份 MUST 有稳定身份记录以绑定源世界绝对路径、世界种子和迁移版本；已有无此身份的目标目录 MUST 被拒绝，匹配身份的既有备份 MAY 作为同一迁移的幂等备份结果复用。备份失败或取消时，源世界 MUST 保持逐字节不变。

#### Scenario: 备份失败不写源世界
- **GIVEN** 备份复制或同步发生失败
- **WHEN** 迁移尚未开始写入区块
- **THEN** 命令 MUST 返回非零，源世界 MUST 保持逐字节不变，且正式备份目录 MUST NOT 被当作成功备份使用

### Requirement: 迁移只重算七种自然值并保留其他状态
迁移 SHALL 以稳定的维度、区块 X、区块 Z 顺序枚举已保存区块，只改写 Overworld。对每个区块，当前值为石头、泥土、草、沙子、砾石、黏土或雪块时 MUST 重算为当前自然材料结果；空气、矿石、箱子、熔炉、其他方块以及掉落物、熔炉状态和箱子内容 MUST 保持不变。无变化区块 MUST NOT 增加 revision；有变化区块 MUST 以 revision 加一的原子提交保存。

#### Scenario: 强制重算自然值但保留非自然负载
- **GIVEN** 旧区块同时含七种自然值、空气、矿石、箱子、熔炉、其他材料和非方块负载
- **WHEN** 迁移处理该区块
- **THEN** 七种自然值 MUST 按新规则重算，其他方块和全部非方块负载 MUST 逐值保持不变

#### Scenario: 非 Overworld 区块保持原样
- **GIVEN** 存档包含 Overworld 以外的维度区块
- **WHEN** 迁移执行
- **THEN** 这些区块 MUST 不被枚举、写入或改写

### Requirement: 迁移可恢复且完成后幂等
迁移 MUST 将稳定排序后的扫描键每 `32` 个组成一个批次，最终不足 `32` 个扫描键 MUST 作为 partial batch 处理。每批 MUST 先原子保存有变化的区块并同步，再以该批最后扫描键原子保存进度；进度 MUST 包含迁移版本、世界种子、备份路径和最后完成区块键。中途失败时命令 MUST 停止并返回非零；使用相同参数重跑 MUST 从已记录进度继续，且不得重复增加已提交区块的 revision。最终 partial batch 的进度保存成功后，系统 MUST 原子记录完成状态；完成后再次执行 MUST 仅报告已完成，不得再次增加任何 revision。

#### Scenario: 保存失败后续跑
- **GIVEN** 迁移已成功提交至少一批区块，后续区块保存失败
- **WHEN** 用户修复故障后以相同参数重跑命令
- **THEN** 命令 MUST 从最后成功记录的区块之后继续，且先前已提交区块 MUST 不被重复写入

#### Scenario: 已完成迁移再次执行
- **GIVEN** 同一世界已以相同迁移版本、种子和备份完成迁移
- **WHEN** 用户再次执行相同迁移命令
- **THEN** 命令 MUST 报告已完成，且所有区块 revision MUST 保持不变

#### Scenario: 最终 partial batch 落盘后控制文件失败
- **GIVEN** 最终不足 `32` 个扫描键的批次已保存并同步，但该批进度写入或随后完成标记失败
- **WHEN** 用户以相同参数重跑迁移
- **THEN** 已保存区块的 revision MUST 不再增加，迁移 MUST 恢复并写入正确进度与完成状态

### Requirement: 既有存档与协议版本保持不变
自然材料生成和迁移 MUST 继续使用区块 schema v8、协议 v15 和世界 metadata v2，不得改变这些格式的字节布局或语义版本。既有 schema v8 往返、future schema 拒绝和区域原子恢复语义 MUST 保持不变。

#### Scenario: 迁移世界继续使用既有版本
- **GIVEN** 已完成自然材料迁移的世界
- **WHEN** 当前程序保存并重新加载该世界，或客户端按协议登录
- **THEN** 区块 schema MUST 为 v8、协议 MUST 为 v15、世界 metadata MUST 为 v2，且既有版本检查与恢复行为 MUST 不变
