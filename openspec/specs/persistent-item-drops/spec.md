# persistent-item-drops Specification

## Purpose

定义固定容量的权威地面掉落物从生成、拾取、兴趣同步、客户端呈现到区块持久化的完整契约，使多人采集不会复制或静默丢失资源，并保持 tick、网络、存档和渲染工作严格有界。

## Requirements

### Requirement: 区块以固定容量持有权威掉落物
服务端 SHALL 在产生掉落物的区块中维护最多 32 个权威掉落物堆；每个活动堆 MUST 具有在其生命周期内唯一且稳定的 ID、已注册物品、`1..64` 的数量和所属方块位置。同物品、同方块位置的掉落物 SHALL 优先合并到最低稳定顺序的未满堆，否则使用最低稳定顺序的空槽；没有合并空间或空槽时，产生掉落物的世界操作 MUST 整体失败。

#### Scenario: 相同位置的同类物品稳定合并
- **GIVEN** 一个区块在目标方块位置已有 63 个泥土物品的掉落物堆
- **WHEN** 权威模拟在同一位置再产生一个泥土物品
- **THEN** 原堆数量变为 64、ID 保持不变且区块不新增活动堆

#### Scenario: 不同位置不合并
- **GIVEN** 一个区块在另一方块位置已有未满的石头掉落物堆并且仍有空槽
- **WHEN** 权威模拟在目标方块位置产生一个石头物品
- **THEN** 系统在最低稳定顺序的空槽创建具有新 ID 的掉落物堆

#### Scenario: 区块容量不足时原子拒绝
- **GIVEN** 目标区块已有 32 个无法接收新物品的活动堆
- **WHEN** 一次世界操作需要在该区块产生新掉落物
- **THEN** 系统 MUST 返回稳定的容量拒绝，且方块、掉落物和玩家状态都保持不变

### Requirement: 掉落物按确定时序拾取和过期
采掘或方块破坏产生的新掉落物 SHALL 在生成 `10` 个活动模拟 tick 后才可拾取，玩家主动丢弃产生的新掉落物 SHALL 在生成 `40` 个活动模拟 tick 后才可拾取；新物品合并到已有堆时 MUST 保留原 ID、generation 和既有寿命时间线，并把整堆拾取禁止窗口延长到不少于新物品的来源延迟，合并所在 tick 若属于活动 tick MUST 计为窗口的第一个 tick。所有掉落物 MUST 在累计 `6000` 个活动模拟 tick 后过期。仅当所属区块位于至少一名 Ready 玩家同维度、区块半径 `2` 的掉落物兴趣范围内时，年龄和拾取延迟才前进。每个活动 tick 中，服务端 MUST 按稳定玩家顺序和稳定掉落物 ID 顺序，让距离方块中心不超过 `1.25` 格的 Ready 玩家依次使用快捷栏和背包的稳定规则尽量接收可拾取物品。

#### Scenario: 采掘掉落物在 10 tick 前不拾取
- **GIVEN** Ready 玩家站在一个刚由采掘或方块破坏生成的掉落物拾取范围内
- **WHEN** 该掉落物尚未累计 `10` 个活动模拟 tick
- **THEN** 玩家完整物品状态和掉落物数量都保持不变

#### Scenario: 主动丢弃物在 40 tick 前不拾取
- **GIVEN** Ready 玩家站在一个刚由玩家主动丢弃生成的掉落物拾取范围内
- **WHEN** 该掉落物尚未累计 `40` 个活动模拟 tick
- **THEN** 所有玩家的完整物品状态和掉落物数量都保持不变

#### Scenario: 合并使用较长来源延迟
- **GIVEN** 一个同物品同位置的已有堆可合并且剩余拾取延迟为 `5` tick
- **WHEN** 采掘产生一个延迟为 `10` tick 的同类物品，或玩家主动丢弃一个延迟为 `40` tick 的同类物品
- **THEN** 两种情况下原堆 ID、generation 和寿命时间线 MUST 保持不变，数量增加 `1`，整堆从新物品产生所在活动 tick 起分别在不足 `10` 或 `40` 个活动 tick 时不可拾取

#### Scenario: 快捷栏不足时继续放入背包
- **GIVEN** 一个可拾取堆有 5 个石头，范围内首位玩家的快捷栏只能再接收 2 个且背包能接收其余 3 个
- **WHEN** 服务端处理该活动 tick
- **THEN** 快捷栏增加 2 个石头、背包增加 3 个石头且掉落物被移除

#### Scenario: 部分拾取保留余量
- **GIVEN** 一个可拾取堆有 5 个石头，范围内首位玩家的快捷栏与背包合计只能再接收 3 个
- **WHEN** 服务端处理该活动 tick
- **THEN** 玩家完整物品状态增加 3 个石头且原掉落物以相同 ID 保留 2 个石头

#### Scenario: 超过单格上限的工具堆拆入多个栏位
- **GIVEN** 一个可拾取堆有 2 把同类镐，且范围内首位玩家至少有两个空栏位
- **WHEN** 服务端处理该活动 tick
- **THEN** 两把镐 MUST 分别进入两个数量为 1 的合法栏位，且原掉落物被移除

#### Scenario: 同 tick 竞争只有一次归属
- **GIVEN** 两名 Ready 玩家在同一可拾取堆范围内且都能通过快捷栏或背包接收全部物品
- **WHEN** 服务端处理该活动 tick
- **THEN** 稳定顺序靠前的玩家获得该堆且另一名玩家不获得重复物品

#### Scenario: 全满玩家不移除掉落物
- **GIVEN** 范围内玩家的快捷栏和背包都没有空间接收可拾取堆
- **WHEN** 服务端处理该活动 tick
- **THEN** 玩家完整物品状态和掉落物数量都保持不变

#### Scenario: 到达寿命后移除
- **GIVEN** 一个掉落物已累计 5999 个活动模拟 tick
- **WHEN** 所属区块再处理一个活动模拟 tick 且该堆没有被拾取
- **THEN** 服务端移除该掉落物且不向任何玩家物品状态添加物品

#### Scenario: 无观察者时寿命暂停
- **GIVEN** 一个掉落物所属区块不在任何 Ready 玩家同维度、区块半径 2 的兴趣范围内
- **WHEN** 服务端推进任意数量的其他世界 tick
- **THEN** 该掉落物的年龄和拾取延迟保持不变

### Requirement: 掉落物兴趣同步严格有界
服务端 SHALL 仅向玩家发送其同维度、脚下区块半径 2 内的掉落物，单名玩家镜像 MUST 不超过 25 个区块和 800 个活动堆。进入兴趣范围 SHALL 发送当前值，合并或部分拾取 SHALL 发送更新，离开兴趣范围、拾完或过期 SHALL 发送移除；每条 upsert 或 remove 消息 MUST 最多包含 32 项，并按稳定 ID 顺序编码。

#### Scenario: 进入兴趣范围获得当前快照
- **GIVEN** 玩家即将进入一个含有多个活动掉落物的区块半径 2 范围
- **WHEN** 该玩家的权威脚下区块变化
- **THEN** 所属连接收到范围内全部当前掉落物且每批不超过 32 项

#### Scenario: 离开兴趣范围清除旧镜像
- **GIVEN** 玩家客户端已有一个即将离开区块半径 2 范围的掉落物
- **WHEN** 该玩家的权威脚下区块变化
- **THEN** 所属连接收到该掉落物的移除且其他玩家的镜像不受影响

#### Scenario: 慢连接不阻塞权威模拟
- **GIVEN** 一个玩家连接停止消费掉落物消息
- **WHEN** 其他玩家继续移动、采集和拾取
- **THEN** 权威 tick 和其他连接 MUST 继续推进，慢连接按现有有界背压策略处理

#### Scenario: Memory 与 TCP 语义一致
- **GIVEN** 相同世界、玩家位置和掉落物变化序列
- **WHEN** 场景分别通过 Memory 与 TCP 执行
- **THEN** 客户端最终可见的掉落物 ID、物品、数量和位置 MUST 一致

### Requirement: 客户端维护有界掉落物镜像
客户端 SHALL 维护最多 800 个权威掉落物的固定容量镜像；upsert MUST 按 ID 新增或替换完整状态，remove MUST 删除对应 ID。无效物品、数量、位置、重复 ID、越界批次或超过容量的更新 MUST 整体拒绝；断开连接、重新登录或切换维度 MUST 清空旧镜像。

#### Scenario: 部分拾取更新现有条目
- **GIVEN** 客户端镜像已有一个数量为 5 的掉落物
- **WHEN** 客户端收到相同 ID、数量为 3 的有效 upsert
- **THEN** 镜像中仍只有一个该 ID 条目且数量变为 3

#### Scenario: 非法批次不部分应用
- **GIVEN** 一批 upsert 同时包含有效条目和重复 ID 或非法数量条目
- **WHEN** 客户端处理该批次
- **THEN** 客户端 MUST 返回错误且整个镜像保持原值

#### Scenario: 会话重置清空镜像
- **GIVEN** 客户端已有上一会话的掉落物镜像
- **WHEN** 连接断开、重新登录或权威维度变化
- **THEN** 下一会话开始前镜像为空且不显示旧掉落物

### Requirement: 图形客户端以固定资源呈现掉落物
图形客户端 SHALL 为权威镜像中的掉落物显示简化物品色块，并只根据已确认的 server tick 和稳定掉落物 ID 计算浮动与旋转；CPU 与 GPU 容量 MUST 固定为 800 个实例，不得随运行时间、消息数量或帧数增长。客户端动画 MUST NOT 反馈为服务端位置或存档状态。

#### Scenario: 权威更新在下一帧生效
- **GIVEN** 图形客户端已显示一个掉落物
- **WHEN** 客户端收到该 ID 的有效 upsert 或 remove
- **THEN** 下一帧使用新数量对应状态或不再显示该掉落物

#### Scenario: 动画不改变权威位置
- **GIVEN** 同一掉落物连续显示多个画面帧
- **WHEN** 客户端计算浮动和旋转
- **THEN** 掉落物镜像中的权威方块位置保持不变且不向服务端发送动画状态

#### Scenario: 自动验证不打开窗口
- **GIVEN** CI 或开发者运行掉落物协议、模拟、存档、客户端或渲染测试
- **WHEN** 自动验证执行
- **THEN** 测试 MUST 可在不启动或聚焦交互式游戏窗口的情况下完成

### Requirement: 掉落物与所属区块原子持久化
区块 payload SHALL 以 schema v3 在同一份区块记录中保存方块状态以及全部掉落物槽的 generation、活动状态、物品、数量、方块位置、年龄和剩余拾取延迟；一次成功保存 MUST 同时提交两类状态。有效 v2 区块 MUST 无损迁移并在下次正常保存时改写为 v3，有效 v1 区块 MUST 沿既有迁移链得到空掉落物集合。损坏、越界或未来 schema MUST 稳定拒绝且不得部分恢复。

#### Scenario: 重启恢复掉落物
- **GIVEN** 一个区块包含尚未过期的掉落物且服务端成功完成刷新
- **WHEN** 服务端从同一世界目录重启并重新加载该区块
- **THEN** 掉落物 ID、物品、数量、方块位置、年龄和拾取延迟均与刷新时一致

#### Scenario: 方块和掉落物保存失败不拆分提交
- **GIVEN** 一次挖掘同时移除方块并在所属区块产生掉落物
- **WHEN** 区块持久化写入失败
- **THEN** 存储 MUST 不发布只含方块修改或只含掉落物修改的新区块记录，并保留现有可重试语义

#### Scenario: v1 区块沿链迁移为空集合
- **GIVEN** 一个有效的区块 schema v1 payload
- **WHEN** 当前版本读取并再次保存该区块
- **THEN** 原方块保持不变、掉落物集合为空且新记录使用 schema v3

#### Scenario: v2 区块无损迁移
- **GIVEN** 一个有效的区块 schema v2 payload
- **WHEN** 当前版本读取并再次保存该区块
- **THEN** 原方块和全部掉落物保持不变且新记录使用 schema v3

#### Scenario: 无效掉落物状态被拒绝
- **GIVEN** 区块 payload 包含重复活动 ID、未知物品、非法数量、越界位置或未来 schema
- **WHEN** 存储边界解码该区块
- **THEN** 系统 MUST 返回错误且不得覆盖磁盘上的最后有效记录

### Requirement: 掉落物协议版本有界且不降级
线上协议 SHALL 升级为 v6，并继续为包含石砖在内的已注册物品掉落物 upsert 和 remove 使用固定字段及显式上限；v5 或其他不匹配版本 MUST 在登录前稳定拒绝，不提供版本协商或降级解码。掉落物消息解码 MUST 拒绝截断、尾随字节、未知枚举、非法数量、越界位置、重复或乱序 ID 和超过 32 项的批次。

#### Scenario: v6 掉落物消息确定性往返
- **GIVEN** 任一有效且按稳定 ID 排序的掉落物 upsert 或 remove 消息
- **WHEN** 消息经过 v6 编码再解码
- **THEN** 解码结果与原值相同且编码字节稳定

#### Scenario: 石砖掉落物可往返
- **GIVEN** 一个有效的石砖掉落物 upsert 消息
- **WHEN** 消息经过 v6 编码再解码
- **THEN** 解码结果保留相同 ID、石砖物品、数量和位置

#### Scenario: 非法掉落物负载被拒绝
- **GIVEN** 一个截断、含尾随字节、重复 ID、乱序 ID、非法物品数量或超限批次的掉落物消息
- **WHEN** v6 解码器处理该消息
- **THEN** 解码器 MUST 返回错误且不得 panic、分配无界内存或输出部分消息

#### Scenario: v5 客户端被拒绝
- **GIVEN** 客户端在握手中声明协议 v5
- **WHEN** 它连接 v6 服务端
- **THEN** 服务端在进入 Play 前返回稳定的不兼容版本结果并关闭登录流
