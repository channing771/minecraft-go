# authoritative-furnaces Specification

## Purpose

为世界提供由区块拥有、服务端权威推进、工作量有界且失败不丢失物品的共享熔炉，使多名玩家可以用煤炭把粗铁熔炼为铁锭，并让熔炉状态与所属区块一起原子持久化。

## Requirements

### Requirement: 熔炉是区块拥有的固定容量状态
每个区块 SHALL 拥有固定 32 个熔炉槽，熔炉状态 MUST 随所属区块一起原子保存与加载，不属于任何玩家，也不得在区块之外维护第二份生命周期真相。活动槽 MUST 记录唯一的区块内方块索引，且该位置 MUST 是熔炉方块；停用槽除 generation 外 MUST 为零值。

#### Scenario: 放置熔炉占用最低可用槽
- **GIVEN** 某区块当前没有活动熔炉
- **WHEN** 玩家在该区块放置一个熔炉
- **THEN** 系统 MUST 启用最低索引的可复用槽，并把该位置写为熔炉方块

#### Scenario: 第 33 个熔炉被原子拒绝
- **GIVEN** 某区块的 32 个熔炉槽都处于活动状态
- **WHEN** 玩家尝试在该区块再放置一个熔炉
- **THEN** 系统 MUST 稳定拒绝，且方块、熔炉状态和玩家物品 MUST 全部保持不变

#### Scenario: 停用槽保留 generation
- **GIVEN** 某熔炉被破坏后其槽位停用
- **WHEN** 系统读取该槽
- **THEN** 该槽 MUST 保留原 generation，其余字段 MUST 为零值

### Requirement: 熔炉引用用 generation 防止旧界面命令生效
熔炉引用 SHALL 由维度、区块位置、槽位与 generation 组成。槽位被重新使用时 generation MUST 递增，使引用旧 generation 的命令稳定拒绝。

#### Scenario: 同位置重建后旧引用失效
- **GIVEN** 玩家已打开某熔炉，随后该熔炉被破坏并在同一位置重新放置
- **WHEN** 玩家用打开时获得的旧引用发送熔炉命令
- **THEN** 系统 MUST 稳定拒绝该命令，且不得修改任何物品

### Requirement: 熔炼只在活动范围内按固定节奏推进
熔炉 SHALL 只在至少一名 Ready 玩家处于同一维度且区块半径 2 的活动范围内推进。系统 MUST 按稳定的维度、区块坐标与槽位顺序处理，使多名玩家的重叠观察在同一 tick 内只推进一次。熔炼进度满 200 tick MUST 产出一个铁锭，燃料每次点燃 MUST 消耗一个煤炭并设置 1600 个燃烧 tick。

#### Scenario: 燃料点燃并开始推进
- **GIVEN** 某活动熔炉输入格有粗铁、燃料格有煤炭、输出格可接收铁锭且剩余燃烧 tick 为 0
- **WHEN** 系统推进该熔炉一个 tick
- **THEN** 系统 MUST 消耗一个煤炭、把剩余燃烧 tick 设为 1600 后再减少一个，并把熔炼进度增加到 1

#### Scenario: 进度满时产出铁锭
- **GIVEN** 某活动熔炉的熔炼进度为 199 且条件仍然有效
- **WHEN** 系统推进该熔炉一个 tick
- **THEN** 系统 MUST 消耗一个粗铁、向输出格加入一个铁锭并把进度归零

#### Scenario: 一个煤炭恰好支持八个铁锭
- **GIVEN** 某活动熔炉只有一个煤炭、足量粗铁且输出容量充足
- **WHEN** 系统持续推进直到燃烧 tick 耗尽
- **THEN** 该熔炉 MUST 恰好产出 8 个铁锭

#### Scenario: 多人重叠观察不重复推进
- **GIVEN** 八名 Ready 玩家的活动范围都覆盖同一个熔炉
- **WHEN** 系统推进一个 tick
- **THEN** 该熔炉的进度与燃烧 tick MUST 各自只变化一次

#### Scenario: 离开活动范围后暂停
- **GIVEN** 某熔炉正在推进
- **WHEN** 所有 Ready 玩家都离开该熔炉的活动范围
- **THEN** 系统 MUST 停止推进该熔炉，且进度与剩余燃烧 tick MUST 保持不变

### Requirement: 条件无效时熔炼完全暂停且不浪费燃料
输入格不是粗铁或输出格无法再接收铁锭时，系统 MUST 同时停止增加熔炼进度和减少剩余燃烧 tick。条件恢复后 MUST 从原值继续，使燃料不会在空转中静默损失。

#### Scenario: 输入为空时冻结
- **GIVEN** 某熔炉有剩余燃烧 tick 与非零熔炼进度，但输入格为空
- **WHEN** 系统推进一个 tick
- **THEN** 熔炼进度与剩余燃烧 tick MUST 都保持不变

#### Scenario: 输出已满时冻结
- **GIVEN** 某熔炉输入格有粗铁且有剩余燃烧 tick，但输出格已达单格上限
- **WHEN** 系统推进一个 tick
- **THEN** 熔炼进度与剩余燃烧 tick MUST 都保持不变

#### Scenario: 条件恢复后从原值继续
- **GIVEN** 某熔炉因输出已满而暂停，其进度为 137、剩余燃烧 tick 为 1463
- **WHEN** 玩家取出输出物品后系统推进一个 tick
- **THEN** 进度 MUST 变为 138 且剩余燃烧 tick MUST 变为 1462

### Requirement: 同一区块的熔炉变化只提升一次 revision
系统 SHALL 在同一 tick 内合并同一区块的全部熔炉变化，使该区块的 revision 至多增加一次。

#### Scenario: 同区块多炉同 tick 变化
- **GIVEN** 同一区块内有多个活动熔炉且都在本 tick 发生变化
- **WHEN** 系统完成该 tick
- **THEN** 该区块的 revision MUST 只增加一次

### Requirement: 熔炉界面使用统一栏位并按容器约束校验
熔炉界面 SHALL 使用统一栏位 `0..38`，其中 `0..35` 是玩家物品栏，36 是输入格，37 是燃料格，38 是输出格。输入格 MUST 只接受粗铁，燃料格 MUST 只接受煤炭，输出格 MUST 只能作为来源而不能作为目标。

#### Scenario: 输入格拒绝非粗铁
- **GIVEN** 玩家已打开某熔炉且物品栏中有煤炭
- **WHEN** 玩家请求把煤炭移动到输入格
- **THEN** 系统 MUST 稳定拒绝，且玩家物品与熔炉状态 MUST 保持不变

#### Scenario: 输出格不能作为目标
- **GIVEN** 玩家已打开某熔炉且物品栏中有铁锭
- **WHEN** 玩家请求把铁锭移动到输出格
- **THEN** 系统 MUST 稳定拒绝，且玩家物品与熔炉状态 MUST 保持不变

#### Scenario: 从输出格取出铁锭
- **GIVEN** 玩家已打开某熔炉，输出格有铁锭且玩家物品栏有空间
- **WHEN** 玩家请求把输出格整堆移动到物品栏
- **THEN** 系统 MUST 同时更新玩家物品与熔炉输出格，并向该玩家确认新的完整物品状态

### Requirement: 跨容器移动要么完整提交要么完全不变
跨玩家物品栏与熔炉的移动 SHALL 在两侧值副本上计算完整结果，只有所有最终槽位都满足约束时才同时提交。过期 sequence、旧熔炉引用、越界索引、非法物品、空来源或容量不足 MUST 拒绝整条命令，且不得部分修改任一侧。

#### Scenario: 容量不足时两侧都不变
- **GIVEN** 玩家物品栏已满且熔炉输出格有铁锭
- **WHEN** 玩家请求把输出格移动到物品栏
- **THEN** 系统 MUST 稳定拒绝，且玩家物品与熔炉状态 MUST 都保持不变

#### Scenario: 非法交换被整体拒绝
- **GIVEN** 玩家已打开某熔炉，输入格有粗铁且玩家选中的物品栏格是煤炭
- **WHEN** 玩家请求交换这两格
- **THEN** 系统 MUST 稳定拒绝，且两侧 MUST 都保持不变

#### Scenario: 多玩家同 tick 移动按稳定顺序串行
- **GIVEN** 两名玩家在同一 tick 对同一熔炉发送移动请求
- **WHEN** 系统处理该 tick
- **THEN** 系统 MUST 按稳定的 session 与 sequence 顺序串行处理，并让两名查看者看到同一最终状态

### Requirement: 破坏熔炉时全部物品原子掉落
采掘熔炉完成前，系统 SHALL 根据工具等级在掉落物副本上预演应保全物品：石镐或铁镐按熔炉本体、输入、燃料、输出的稳定顺序预演，等级不足时不得加入熔炉本体但 MUST 按输入、燃料、输出顺序保全全部内部物品。只有全部应掉落物品都能完整放入时才清除方块、停用槽位并提交掉落物；容量不足时方块、熔炉状态、掉落物与 revision MUST 全部保持不变。

#### Scenario: 石镐破坏满内容熔炉时全部掉落
- **GIVEN** 某活动熔炉的输入、燃料、输出三格都有物品且所属区块掉落物槽充足
- **WHEN** 玩家用石镐完成该熔炉的权威采掘
- **THEN** 系统 MUST 在同一操作中产生熔炉本体与三格物品的掉落物，并停用该熔炉槽

#### Scenario: 错误工具仍保全内部物品
- **GIVEN** 某活动熔炉三格都有物品且所属区块掉落物槽足以接收三格内容
- **WHEN** 玩家用普通非工具物品完成该熔炉的权威采掘
- **THEN** 系统 MUST 停用熔炉并只产生三格内容物，不得产生熔炉本体掉落

#### Scenario: 错误工具破坏空熔炉不产生掉落
- **GIVEN** 某活动熔炉三格都为空
- **WHEN** 玩家用等级不足的手持状态完成该熔炉的权威采掘
- **THEN** 系统 MUST 清除方块并停用槽位，且不得创建掉落物

#### Scenario: 掉落容量不足时整体拒绝
- **GIVEN** 某活动熔炉有内部物品但所属区块的掉落物槽无法容纳本次应保全的全部物品
- **WHEN** 玩家使用任意工具等级完成该熔炉的权威采掘
- **THEN** 系统 MUST 稳定拒绝，且方块、熔炉状态、掉落物与 revision 全部保持不变

### Requirement: 查看关系由服务端维护并在失效时精确关闭
每名玩家 SHALL 最多同时查看一个熔炉，多名玩家 MUST 可以同时查看同一个熔炉。服务端 MUST 用权威射线验证六格距离与目标方块后才建立查看关系，并把完整熔炉状态发送给全部当前查看者；熔炉状态 MUST NOT 发送给仅订阅区块但未打开界面的玩家。距离超出、目标方块改变、generation 变化、区块卸载、维度 reset 或断开连接时，系统 MUST 移除查看关系并发送精确一次关闭通知。

#### Scenario: 服务端验证后建立查看关系
- **GIVEN** Ready 玩家视线内六格范围有活动熔炉
- **WHEN** 玩家发送打开请求
- **THEN** 服务端 MUST 用权威射线验证目标，并向该玩家发送完整熔炉状态

#### Scenario: 未打开界面的玩家收不到熔炉状态
- **GIVEN** 某玩家订阅了含活动熔炉的区块但没有打开界面
- **WHEN** 该熔炉状态发生变化
- **THEN** 系统 MUST NOT 向该玩家发送熔炉状态

#### Scenario: 走远后精确关闭一次
- **GIVEN** 玩家已打开某熔炉
- **WHEN** 玩家移动到超过六格的距离
- **THEN** 系统 MUST 移除查看关系并只发送一次关闭通知

#### Scenario: 断开连接直接移除查看者
- **GIVEN** 玩家已打开某熔炉
- **WHEN** 该玩家断开连接
- **THEN** 系统 MUST 移除其查看关系，且其他查看者 MUST 继续收到状态更新

### Requirement: 熔炉状态跨重启完整恢复且不补算离线进度
区块存档 SHALL 保存熔炉的三格物品、熔炼进度与剩余燃烧 tick。服务端重启后 MUST 恢复这些原值，并且 MUST NOT 按墙钟补算停服期间的进度；只有区块重新进入活动范围后才继续推进。

#### Scenario: 重启后恢复原值
- **GIVEN** 某熔炉在进度 137、剩余燃烧 tick 1463 时正常关服
- **WHEN** 服务端重新启动并加载该区块
- **THEN** 三格物品、进度与剩余燃烧 tick MUST 与关服时相同

#### Scenario: 停服时间不产生进度
- **GIVEN** 服务端停止运行一段真实时间后重新启动
- **WHEN** 玩家重新进入该熔炉的活动范围并推进一个 tick
- **THEN** 进度 MUST 只从恢复值增加 1，不得补算停服期间的 tick

### Requirement: 熔炉热路径保持有界且不分配
系统 SHALL 用固定容量结构与复用 scratch 推进熔炉，最坏情况下每 tick 检查量 MUST 不超过 8 名玩家 × 25 个活动区块 × 32 个槽。稳定态推进 MUST NOT 在权威 tick 热路径产生堆分配。

#### Scenario: 满负载推进不分配
- **GIVEN** 八名 Ready 玩家的活动范围合计覆盖 25 个区块且每个区块有 32 个活动熔炉
- **WHEN** 系统推进一个 tick
- **THEN** 推进过程 MUST NOT 产生堆分配，且工作量 MUST 保持在固定上限内
