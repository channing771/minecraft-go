## MODIFIED Requirements

### Requirement: 固定配方具有稳定语义
系统 SHALL 定义五条稳定固定配方：recipe ID `1` 每次消耗 4 个石头并产出 4 个石砖，ID `2` 消耗 8 个石头并产出 1 个熔炉，ID `3` 消耗 9 个铁锭并产出 1 个铁块，ID `4` 消耗 3 个石头并产出 1 个石镐，ID `5` 消耗 3 个铁锭并产出 1 个铁镐；recipe ID、原料、数量和产物 MUST 由服务端定义，客户端不得声明或覆盖这些值。

#### Scenario: 石砖配方可查询
- **GIVEN** 客户端和服务端运行协议 v8
- **WHEN** 系统读取 recipe ID `1`
- **THEN** 该配方稳定表示 4 个石头转换为 4 个石砖

#### Scenario: 熔炉配方可查询
- **GIVEN** 客户端和服务端运行协议 v8
- **WHEN** 系统读取 recipe ID `2`
- **THEN** 该配方稳定表示 8 个石头转换为 1 个熔炉

#### Scenario: 铁块配方可查询
- **GIVEN** 客户端和服务端运行协议 v8
- **WHEN** 系统读取 recipe ID `3`
- **THEN** 该配方稳定表示 9 个铁锭转换为 1 个铁块

#### Scenario: 石镐配方可查询
- **GIVEN** 客户端和服务端运行协议 v8
- **WHEN** 系统读取 recipe ID `4`
- **THEN** 该配方稳定表示 3 个石头转换为 1 个石镐

#### Scenario: 铁镐配方可查询
- **GIVEN** 客户端和服务端运行协议 v8
- **WHEN** 系统读取 recipe ID `5`
- **THEN** 该配方稳定表示 3 个铁锭转换为 1 个铁镐

#### Scenario: 未知配方被拒绝
- **GIVEN** 玩家具有任意有效完整物品状态
- **WHEN** 玩家请求 recipe ID `0` 或其他未注册值
- **THEN** 系统 MUST 稳定拒绝且完整物品状态保持不变

## ADDED Requirements

### Requirement: 工具合成遵守单格容量并沿用玩家 schema v3
石镐与铁镐 SHALL 作为新增稳定物品 ID 写入现有玩家 schema v3，每格最多保存一个。工具配方只有在扣料后存在一个可接收完整单件产物的栏位时才能提交；当前程序 MUST 跨重连和重启恢复工具，旧程序遇到未知工具 ID 时 MUST 拒绝玩家文件且不得覆盖。

#### Scenario: 扣料释放的栏位接收工具
- **GIVEN** 36 格全部非空且最低原料栏位恰好有 3 个石头
- **WHEN** 玩家成功请求一次石镐配方
- **THEN** 该石头栏位被清空后接收一个石镐，其他栏位保持不变

#### Scenario: 已有工具不能接收第二个
- **GIVEN** 玩家有足量铁锭但扣料后没有空栏位且唯一铁镐栏位已有一个铁镐
- **WHEN** 玩家请求铁镐配方
- **THEN** 服务端 MUST 保留全部铁锭并且不得创建第二个铁镐

#### Scenario: 重启恢复工具
- **GIVEN** 玩家已经合成工具且服务端成功刷新玩家 schema v3
- **WHEN** 服务端重启并让同一玩家重新连接
- **THEN** 玩家 MUST 恢复相同工具、数量和选中栏位

#### Scenario: 旧程序安全拒绝工具物品
- **GIVEN** 玩家 schema v3 文件含当前程序新增的工具物品 ID
- **WHEN** 不认识该 ID 的旧程序尝试加载玩家
- **THEN** 旧程序 MUST 拒绝登录且不得覆盖原文件
