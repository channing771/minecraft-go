## Why

M3 已经完成多人权威交互，但玩家仍可凭客户端声明无限放置方块，挖掘也不会产生资源，尚未形成生存玩法的资源约束。M4A 先交付一个可独立验收的最小闭环：玩家挖掘获得资源、从权威快捷栏选择资源、放置成功后消耗资源，并在重连和重启后保持一致。

## What Changes

- 新增稳定 `ItemID`、固定 9 格快捷栏、单格最多 64 个物品，以及方块与可放置物品的显式映射。
- 服务端权威执行采集与消耗：可采集方块被成功挖掘后直接加入快捷栏；快捷栏无空间时拒绝挖掘；仅在方块成功放置后扣除一个物品。
- 客户端可用数字键 `1–9` 选择栏位，并显示固定大小的快捷栏、物品数量和选中状态；客户端显示是服务端状态的只读镜像。
- **BREAKING**：线上协议从 v2 升级为 v3，放置命令改为引用快捷栏栏位，并新增选中栏位与完整快捷栏快照消息；v2 客户端稳定拒绝，不提供双版本协商。
- 玩家存档 schema 从 v1 升级为 v2，保存快捷栏和选中栏位；旧 v1 存档确定性迁移为空快捷栏，世界和区块存档格式不变。
- Memory 与 TCP 继续复用同一登录、命令和发布语义；多名玩家的快捷栏相互隔离，任何快捷栏状态只发送给所属玩家。
- 本批不实现掉落物实体、工具与耐久、背包界面、箱子、合成、熔炼、生命饥饿、光照或怪物。掉落物加入时再把成功挖掘后的直接入栏替换为实体拾取，不改变快捷栏契约。

## Capabilities

### New Capabilities

- `authoritative-hotbar`: 定义固定快捷栏的权威采集与放置消耗、客户端同步与呈现、玩家存档迁移、多人隔离及有界性能行为。

### Modified Capabilities

无。`openspec/specs/` 当前没有已归档的相关主规格。

## Impact

- 受影响包：`internal/core`、`internal/sim`、`internal/network`、`internal/storage`、`internal/server`、`internal/client`、`internal/render`、`cmd/mcgo` 与 `internal/archcheck`；现有 `internal/gfx` 接口足够，预计无需扩展。
- 受影响契约：协议版本与 golden/fuzz 夹具、玩家存档 schema 与迁移链、玩家快照/哈希、交互拒绝原因、Memory/TCP 一致性和重启恢复测试。
- 并发与性能：快捷栏使用固定容量值类型；只在登录、选择变化或采集/消耗成功时发布完整快照，不在每 tick 或每帧生成无界工作；不得放宽现有 M3C 性能门禁。
- 依赖：优先复用现有字体、GPU 抽象、协议编解码和玩家持久化，不新增第三方依赖。
- 文档：更新 README 操作说明、协议版本说明和玩家存档兼容说明；自动验证不启动前台游戏窗口。
