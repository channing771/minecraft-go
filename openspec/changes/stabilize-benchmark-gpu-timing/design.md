## Context

动机与实测数据见 `proposal.md`。当前 `measureGPUCompletion` 对 2048 次「编码 → 提交 → `Poll(true)`」逐次计时，每个样本进入固定容量的 `client.LatencyRecorder`。`internal/gfx` 目前只暴露 `Submit` 与 `Poll`，没有查询集合抽象；`RequestDevice` 也没有声明任何 required feature。

本机适配器已确认支持 `FeatureNameTimestampQuery`（44 个 feature 中包含该项，且可成功创建带该 feature 的设备）。

## Goals / Non-Goals

**Goals:**

- 让 `remote_gpu_complete` 反映远端角色与昵称的真实 GPU 执行时间，且分辨率远细于 `1.28ms`。
- 让性能门禁只在指标分辨率足够时才施加相对回归判定。
- 降低 benchmark 的持续热负载，并让 GPU 采样不发生在刚结束的满载尾部。
- 保持既有 workload 结构、样本数、分辨率与绝对门禁不变。

**Non-Goals:**

- 不引入通用 GPU profiling 框架、逐 pass 计时或火焰图。
- 不改变 still/flying 的时长、相机脚本或帧时间统计口径。
- 不为不支持时间戳的设备提供墙钟降级路径；那会让同名指标在不同机器上含义不同。

## Decisions

### 1. 用 GPU 时间戳替代 `Poll` 往返

`internal/gfx` 增加固定容量的时间戳查询集合抽象，并在渲染 pass 的开始与结束写入时间戳。一次样本取「结束时间戳 − 开始时间戳」并按设备的时间戳周期换算为纳秒。`Poll` 仍用于取回结果，但不再参与计时，其 `1.28ms` 节拍因此退出指标。

`gfx` 在请求设备时声明该 feature 为必需。若适配器不支持，benchmark MUST 以明确错误失败并且不写出报告，而不是回退到墙钟测量：同名指标在不同机器上代表不同物理量，比缺少指标更危险。非 benchmark 路径不受影响。

否决继续用墙钟并加大单次提交的绘制量：实测 64 次 clear 仍被量化到 `1.28ms` 的整数倍，只是把跳变搬到更高倍数，不解决问题。

### 2. 相对门禁只作用于分辨率足够的指标

`perfcheck` 对每个受检指标显式区分「可做相对回归判定」与「只做绝对上限判定」。判定依据是指标的测量分辨率是否远细于 `20%` 阈值。改用 GPU 时间戳后 `remote_gpu_complete` 重新具备足够分辨率，因此仍保留相对判定；本决策的作用是把这条规则写进门禁，使今后任何量化指标不会再被误配相对阈值。

绝对上限保持现值，不放宽。

### 3. 阶段之间加入冷却窗口

在预热与 still 之间、still 与 flying 之间、flying 与 GPU 采样之间各插入一段固定冷却等待，期间不提交渲染工作。冷却只影响阶段之间的时间轴，不改变任何被采集的量；报告中记录冷却时长以便复现。

否决降低帧率上限：still/flying 的帧时间分位数是核心指标，限帧会把它们变成上限周期本身，直接破坏测量。

### 4. scenario v12 与迁移

GPU 指标语义改变、阶段时间轴改变，因此 producer 标记 scenario v12，比较器只保留唯一显式 `11:12` 迁移，`10:11` 退役。历史 v6–v11 报告继续按各自规则读取。

### 5. 与 M4G 的先后关系

M4G 的 v11 候选保持冻结，不因本 change 重跑或改写。本 change 完成并建立 M5 scenario v12 基线后，M4G 再继续其归档流程；M4G 的 v11 正式链失败报告只保留为诊断证据。

## Risks / Trade-offs

- [强制要求时间戳 feature 会让不支持的设备无法产出 benchmark] → 这是有意的：宁可缺指标也不要同名不同义。非 benchmark 路径不声明该 feature。
- [时间戳只覆盖 pass 执行，不含提交调度开销] → 这正是目标；提交侧开销由既有的 avatar/name tag submit 指标覆盖。
- [冷却窗口拉长总时长] → 以时间换可重复性与更低热负载；时长写入报告并记入基线证据。
- [又一次 scenario 升级需要重建基线] → 与 M4G 的 v11 基线合并为一次 v12 正式链，避免连续两次基线重建。

## Migration Plan

1. 先加 gfx 时间戳能力与其单元测试，确认无窗口路径可用。
2. 改探针与门禁，更新 producer 为 v12 并退役 `10:11`。
3. 加入冷却窗口并更新文档。
4. 完成全仓门禁并冻结候选，取得一次性授权后执行 v12 正式链（Memory 一次、TCP 一次）。
5. 提升 M5 基线为 v12，然后回到 M4G 完成其归档。
