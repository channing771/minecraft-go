# companion-world-actions Specification

## Purpose

定义伙伴采掘与放置的权威原子性：动作复用玩家的全部既有规则（计时、工具、耐久、放置校验），其多方可观察变更在同一权威 tick 内原子成立或整体不发生。

## ADDED Requirements

### Requirement: 伙伴采掘复用玩家计时规则且三方原子

`mine` 步骤 SHALL 先把伙伴带入目标方块的交互距离（复用 `go_to` 的移动与寻路语义），随后按既有玩家采掘规则持续采掘：所需 tick 由 `miningRule`（方块、持握工具）唯一决定，交互距离与 Ready 区块校验与玩家共用同一实现。采掘完成的同一权威 tick 内 MUST 原子完成三方：目标方块改为空气、按既有规则扣除工具耐久（含损坏形态）、可收获产物直接加入伙伴 36 格背包；任一方无法完成时该 tick MUST NOT 变更任何一方。采掘目标 MUST 是具有单一 `BlockDrop` 且不是箱子或熔炉的普通方块——Planner 契约与权威模拟双重拒绝容器与多掉落方块。伙伴背包没有容纳产物的空位时任务 MUST 以稳定原因失败且 MUST NOT 破坏方块。目标方块在采掘过程中被其他 actor 改变时，采掘进度 MUST 失效并按目标变化语义处理，MUST NOT 破坏新方块。

#### Scenario: 完整采掘链三方原子成立

- **GIVEN** 伙伴背包有一把完好的石镐，交互距离内有一个煤矿石方块
- **WHEN** 采掘按所需 tick 完成的那一权威 tick
- **THEN** 方块 MUST 变为空气、石镐耐久 MUST 按既有规则扣减、对应产物 MUST 直接出现在伙伴背包中，三者 MUST 在同一 tick 内全部成立

#### Scenario: 背包无空位不破坏方块

- **GIVEN** 伙伴 36 格背包已满且交互距离内有一个可采掘方块
- **WHEN** 任务尝试执行采掘
- **THEN** 方块 MUST 保持不变，任务 MUST 以稳定原因失败并广播事件，背包 MUST 不变

#### Scenario: 容器与多掉落方块被拒绝

- **GIVEN** 交互距离内分别有一个箱子和一个熔炉
- **WHEN** 计划包含以其为目标的 `mine` 步骤
- **THEN** 该步骤 MUST 被拒绝（计划校验或权威模拟至少一方拦截），方块 MUST NOT 被破坏

#### Scenario: 目标变化令进度失效

- **GIVEN** 伙伴正在采掘一个方块且进度已过半
- **WHEN** 其他 actor 在完成前替换了该位置的方块
- **THEN** 既有进度 MUST 失效，任务 MUST 按目标变化语义处理，新方块 MUST NOT 被破坏或继承进度

### Requirement: 伙伴放置单 tick 原子扣料写入

`place` 步骤 SHALL 先把伙伴带入目标位置的交互距离，随后在单一权威 tick 内完成：按既有玩家放置规则校验（目标为空气、放置合法性与碰撞判定、Ready 区块），从伙伴背包原子扣除一件对应物品并写入方块；任一校验不通过时 MUST NOT 扣料。放置的方块 MUST 来自固定注册表且快照背包显示伙伴持有；任务执行中背包已无对应物品时任务 MUST 以稳定原因失败。

#### Scenario: 放置成功原子扣料

- **GIVEN** 伙伴背包有三件橡木板且交互距离内的目标位置为空气
- **WHEN** 放置在权威 tick 执行
- **THEN** 目标位置 MUST 出现橡木板方块，背包对应堆 MUST 恰好减少一件，二者 MUST 在同一 tick 内成立

#### Scenario: 校验失败不扣料

- **GIVEN** 伙伴背包持有物品但目标位置已被其他 actor 放置方块
- **WHEN** 任务执行放置
- **THEN** 放置 MUST 被拒绝，背包 MUST 保持不变，任务 MUST 以稳定原因失败或按目标变化语义处理

#### Scenario: 物品耗尽令任务失败

- **GIVEN** 计划包含两次连续 `place` 同种方块而伙伴背包只剩一件
- **WHEN** 第一次放置完成后执行第二次
- **THEN** 第二次放置 MUST NOT 发生，任务 MUST 以稳定原因失败，背包与世界的已成交变更 MUST 保留
