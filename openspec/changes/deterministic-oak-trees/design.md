## Context

现有 `internal/worldgen.Generator` 的 `BaseBlockAt` 与 `GenerateChunk` 已分别提供单点和整区块地形生成，`oreHash` 已提供种子、三维坐标和 salt 的稳定混合。树木必须在该生成器内保持纯计算，并与已有自然材料和矿石规则组合；动机见 [proposal.md](proposal.md)。

## Goals / Non-Goals

**Goals:**

- 让橡树在任意世界坐标处可独立重算，且单点与整区块输出完全一致。
- 用固定 8×8 候选格和既有 `oreHash` 得到跨区块、负坐标稳定的候选。
- 以正常无窗口客户端链路加入可审查的 `oak-grove` 场景。

**Non-Goals:**

- 不改变协议、区块 schema、世界 metadata、现有 block/item ID 或已保存区块。
- 不增加树种、掉落物、物理规则、迁移工具或生成配置入口。

## Decisions

### 候选由固定格和既有哈希唯一确定

世界生成包定义下列常量：

```go
const (
	oakTreeCellShift = 3 // 8×8
	oakTreeSalt      = uint64(0xA24BAED4963EE407)
)
```

对候选格 `(cellX, cellZ)`，以 `(cellX, 0, cellZ)` 调用 `oreHash`。仅当 `hash&1 == 0` 时生成；候选 X 使用 `(hash>>1)&7`，候选 Z 使用 `(hash>>4)&7`，树高使用 `4+(hash>>7)%3`。格坐标必须使用向下取整的 8 格划分，使负坐标与正坐标连续。

选择复用 `oreHash` 而非新增随机数状态或噪声层：它已具有所需的稳定性，且不会引入调用顺序依赖。否决逐区块随机候选，因为树冠在区块边界会依赖加载顺序；否决可调树木密度，因为本变更没有调参需求。

### 覆盖从原始地形判定并按原木优先合并

根位置是候选 XZ 的 `Generator.HeightAt` 所得草地表上方第一格，树干顶为 `topY = root.Y + height - 1`。只有根下方按既有自然材料规则为草地且目标位置原始值为空气时才写树干。树叶候选层固定为：`topY-2` 与 `topY-1` 的去角 5×5，`topY` 的完整 3×3，`topY+1` 的中心与四个水平相邻格；树叶仅覆盖原始空气。

单点查询从可能覆盖目标位置的相邻候选格推导候选，先判原木覆盖、再判树叶覆盖，最后保留原始地形值。`GenerateChunk` 对每个位置复用此单点纯判断，避免把候选遍历顺序编码为结果。选择按坐标重算而不是缓存跨区块结构，因为小而固定的候选范围消除了共享状态、锁与失效问题；否决先写树冠再修补树干，因为它使优先级依赖写入顺序。

所有树干和树叶写入前均检查世界有效高度范围。树叶继续使用既有 `LeavesID`，因此其渲染和无碰撞语义不另行实现。

### 新地形生成保持唯一数据所有权

`Generator` 继续作为新地形方块内容的唯一计算来源；存储层继续拥有已保存区块，加载后的区块不调用重新生成逻辑。实现只触及 `internal/worldgen` 与对应测试，不改变 `world` 对 `network` 的依赖边界，也不引入 goroutine、I/O 或锁。视觉夹具只通过客户端镜像写入其固定区块，并让既有 mesher、renderer 和 upload 收敛。

### 视觉场景在既有表末尾追加

`oak-grove` 使用固定世界种子、固定生成区块、固定正午和固定相机。它在所有现有场景之后注册，且沿用既有预热、无窗口抓帧与双阈值比较。选择独立场景而不是改写 `materials-showcase`，使树木生成可单独定位，且不扩大既有材料夹具的语义。

## Risks / Trade-offs

- [树冠接近世界上界] → 每次覆盖都检查有效 Y 范围，并以边界测试验证无越界写入。
- [负坐标格划分错误] → 使用向下取整的格坐标，并以跨正负区块的单点/整块一致性测试覆盖。
- [树冠跨区块遗漏或重复] → 对目标位置枚举所有可能覆盖它的相邻候选格，按原木优先的无序合并判定结果。
- [视觉夹具未走生产链路] → 测试固定夹具经 mirror 产生 dirty mesh，并在无窗口完整路径抓取和比对。

## Migration Plan

部署后新规则只用于首次生成且尚未保存的区块；已保存区块按原内容加载，不执行迁移或批量重写。回退到不含本变更的版本不会改变已有已保存区块内容；未保存的新区域会按回退版本的既有规则生成。协议 v15、区块 schema v8 与世界 metadata v2 保持不变。
