## Why

M4A 已建立权威快捷栏，但成功挖掘会把物品直接放入快捷栏，玩家看不到资源落地、竞争拾取或满栏后保留资源，仍不是完整的采集体验。M4B 用一个固定上限、可随区块原子存档的掉落物闭环替换这项临时行为，同时保持现有多人、存档和性能边界。

## What Changes

- 成功挖掘石头、泥土或草后，不再直接修改快捷栏，而是在被挖方块中心创建或合并一个权威掉落物；方块修改与掉落物属于同一权威区块状态。
- 每个区块最多保存 32 个掉落物堆，同物品、同方块位置的堆最多合并到 64；没有可合并堆或空槽时拒绝挖掘，方块保持不变。
- 掉落物生成后 10 tick 才可拾取，存活 6000 tick；Ready 玩家进入 1.25 格拾取范围后按稳定顺序尽量装入快捷栏，满栏时剩余数量留在地面。
- 每名玩家只接收同维度、脚下区块半径 2 内的掉落物，最坏 25 个区块、800 个堆；进入兴趣范围发送当前值，合并/部分拾取发送更新，离开、拾完或过期发送移除。
- 客户端以固定 roster 和专用渲染器显示简化物品色块；旋转/浮动只由客户端根据 server tick 与掉落物 ID 计算，不增加服务端状态。
- **BREAKING**：线上协议从 v3 升为 v4，新增有界掉落物 upsert/remove 消息并稳定拒绝 v3；不提供版本协商。
- **BREAKING**：区块 payload schema 从 v1 升为 v2，保存掉落物槽、槽 generation、物品、位置、生成年龄和拾取延迟；v1 区块迁移为空掉落物集合。玩家存档 schema v2 不变。
- 本批不实现投掷/丢弃、水平或重力物理、磁吸、通用实体/ECS、背包、合成、装备、掉落物跨区块移动、怪物或伤害。

## Capabilities

### New Capabilities

- `persistent-item-drops`: 定义区块内权威掉落物的生成、合并、拾取、过期、兴趣同步、客户端呈现与原子存档行为。

### Modified Capabilities

- `authoritative-hotbar`: 把成功挖掘直接入栏和满栏拒绝改为生成持久掉落物，并把唯一支持的线上协议从 v3 升级为 v4。

## Impact

- 受影响包：`internal/core`、`internal/world`、`internal/sim`、`internal/network`、`internal/storage`、`internal/server`、`internal/client`、`internal/render`、`cmd/mcgo`、`cmd/mcgod` 与 `internal/archcheck`。
- 受影响契约：区块值/Clone/容量估算与状态哈希、区块 schema/golden/fuzz/迁移、协议 packet 表/golden/fuzz、区块获取和保存快照、多人兴趣发布、客户端 reset 与渲染容量。
- 一致性：掉落物存入产生它的区块 payload，区块保存一次提交方块和掉落物；不新增跨文件事务或独立掉落物数据库。
- 并发与性能：模拟单写者拥有掉落物；每区块 32、兴趣半径 2、单观察者 800 是硬上限；网络按固定小批次发送，tick/渲染热路径不得出现无界分配或阻塞 I/O。
- 依赖与资源：复用现有标准库、协议、存储、字体/颜色和 `gfx` 接口，不新增第三方依赖或二进制素材。
- 文档与验证：更新 README、LAN/存档兼容说明和性能门禁；所有自动验证保持 headless，不启动或聚焦游戏窗口。
