## Context

M4E 已在 `internal/core` 中以稳定 ID 定义石砖、熔炉和铁块配方，现有 `CraftRecipe` 消息、`cmd/mcgo` 点击处理和服务端权威执行路径都能处理任意已注册配方。缺口集中在 `internal/render/hotbar.go`：当前只绘制并命中石砖按钮。

HUD 使用同一固定上传缓冲分别绑定 viewport、quad 和 glyph。当前最大 quad 区间为 `256 + 84 × 48 = 4288` 字节，但 glyph 固定从 `4096` 开始，两个区间发生重叠；编码 glyph 时可能覆盖末尾 quad。三条固定配方需要 9 个 quad 和 6 个 glyph，仍不超过现有熔炉 overlay 的 10 个 quad 和 6 个 glyph 上限。

## Goals / Non-Goals

**Goals:**

- 用现有固定配方、权威物品镜像和合成消息完成三条配方的图形入口。
- 让绘制和命中测试共享同一配方顺序与几何规则。
- 保持 HUD 上传区域固定、有界且互不重叠。
- 让项目入口说明准确反映 M4E、协议 v7、玩家 schema v3 和区块 schema v4。

**Non-Goals:**

- 不增加配方、合成网格、批量合成、队列或客户端预测。
- 不引入动态配方注册器、分页、滚动、选择状态或第二套 UI pipeline。
- 不修改服务端 tick、线上协议、存档格式、性能阈值或 benchmark scenario。

## Decisions

### 1. 配方顺序固定在渲染层

`internal/render` 使用固定的三个 recipe ID，顺序为石砖、熔炉、铁块。绘制函数按该顺序生成三行，按钮命中函数遍历同一顺序并返回对应 ID。配方原料、产物和可合成判断继续调用 `core.Recipe` 与 `Inventory.Craft`，不复制服务端规则。

固定列表是当前三条配方的最小实现。否决在 `core` 增加通用枚举或注册器，因为服务端已有稳定查询入口，只有 UI 需要显示顺序；当固定配方数量增长到需要分页、分类或外部扩展时，再提升为共享目录。

### 2. 三条配方垂直排列且不增加客户端状态

第一行沿用当前背包最上方的配方位置，另外两行以现有固定格子间距继续向上排列。每行仍包含输入格、输出格和一个按钮；每个按钮独立使用最后确认背包计算颜色。打开熔炉时继续完全替换配方区域，不同时绘制两种 overlay。

否决单行左右切换方案，因为它需要新增选择状态、切换按钮、重置语义和更多命中路径，却不能增加当前三条配方的能力。

### 3. 在固定缓冲内分离 quad 与 glyph 区域

保持现有最大实例数不变，将 glyph offset 计算为 quad 区间末尾向上对齐到 256 字节后的值。测试直接断言 `hotbarGlyphOffset >= hotbarQuadOffset + hotbarQuadSize`，并继续锁定 buffer 总大小和最大实例编码。

该调整只增加少量固定缓冲字节，不引入每帧分配。否决动态 buffer 扩容，因为布局上限在编译期已知，动态容量会增加热路径状态和错误面。

### 4. 权威数据流保持不变

点击按钮后，`cmd/mcgo` 从客户端最后确认镜像调用 `Inventory.Craft` 做发送前可用性判断，只发送 sequence 与 recipe ID。客户端不改写镜像；服务端仍按会话序列和当前权威物品状态执行最终校验并发布完整状态。Memory 与 TCP 继续走同一消息和模拟路径。

本变更不新增跨 goroutine 数据、共享可变状态或包依赖；`render` 只依赖现有 `core`，`sim`、`world`、`network` 和 `storage` 均不新增依赖。

### 5. 项目事实与行为同批同步

`AGENTS.md`、`CLAUDE.md` 和 `openspec/config.yaml` 的当前基线统一为 M4E，并明确已交付资源链、协议 v7、玩家 schema v3 与区块 schema v4。`README.md` 只更新配方入口相关的操作说明和当前限制，不重写其他内容。

## Risks / Trade-offs

- [固定三行在很矮的 framebuffer 上可能超出可见区域] → 沿用当前固定背包对最小可用高度的假设，并用常用 framebuffer 尺寸测试三行与背包格互不重叠；需要自适应布局时另立变更。
- [固定 UI 列表可能在新增配方后遗漏] → 测试锁定当前三个稳定 ID；配方数量明显增长时再引入共享目录，不为未来需求提前抽象。
- [移动 glyph offset 可能改变绑定范围] → 测试锁定 256 字节对齐、区域非重叠、总 buffer 大小和最大实例上传，自动测试不创建前台窗口。

## Migration Plan

无需数据或协议迁移。实现可作为普通客户端升级发布；旧客户端仍只显示石砖入口，但与协议 v7 服务端兼容。回退只需恢复渲染布局和项目说明，不影响已有世界、玩家或区块存档。
