## MODIFIED Requirements

### Requirement: 掉落物与所属区块原子持久化
区块 payload SHALL 以 schema v3 在同一份区块记录中保存方块状态以及全部掉落物槽的 generation、活动状态、物品、数量、方块位置、年龄和剩余拾取延迟；一次成功保存 MUST 同时提交两类状态。有效 v2 区块 MUST 无损迁移并在下次正常保存时改写为 v3，有效 v1 区块 MUST 沿既有迁移链得到空掉落物集合。损坏、越界或未来 schema MUST 稳定拒绝且不得部分恢复。

#### Scenario: 重启恢复掉落物
- **GIVEN** 一个区块包含尚未过期的掉落物且服务端成功完成刷新
- **WHEN** 服务端从同一世界目录重启并重新加载该区块
- **THEN** 掉落物 ID、物品、数量、方块位置、年龄和拾取延迟均与刷新时一致

#### Scenario: 方块和掉落物保存失败不拆分提交
- **GIVEN** 一次挖掘同时移除方块并在所属区块产生掉落物
- **WHEN** 区块持久化写入失败
- **THEN** 存储 MUST 不发布只含方块修改或只含掉落物修改的新区块记录，并保留现有可重试语义

#### Scenario: v1 区块沿链迁移为空集合
- **GIVEN** 一个有效的区块 schema v1 payload
- **WHEN** 当前版本读取并再次保存该区块
- **THEN** 原方块保持不变、掉落物集合为空且新记录使用 schema v3

#### Scenario: v2 区块无损迁移
- **GIVEN** 一个有效的区块 schema v2 payload
- **WHEN** 当前版本读取并再次保存该区块
- **THEN** 原方块和全部掉落物保持不变且新记录使用 schema v3

#### Scenario: 无效掉落物状态被拒绝
- **GIVEN** 区块 payload 包含重复活动 ID、未知物品、非法数量、越界位置或未来 schema
- **WHEN** 存储边界解码该区块
- **THEN** 系统 MUST 返回错误且不得覆盖磁盘上的最后有效记录

### Requirement: 掉落物协议版本有界且不降级
线上协议 SHALL 升级为 v6，并继续为包含石砖在内的已注册物品掉落物 upsert 和 remove 使用固定字段及显式上限；v5 或其他不匹配版本 MUST 在登录前稳定拒绝，不提供版本协商或降级解码。掉落物消息解码 MUST 拒绝截断、尾随字节、未知枚举、非法数量、越界位置、重复或乱序 ID 和超过 32 项的批次。

#### Scenario: v6 掉落物消息确定性往返
- **GIVEN** 任一有效且按稳定 ID 排序的掉落物 upsert 或 remove 消息
- **WHEN** 消息经过 v6 编码再解码
- **THEN** 解码结果与原值相同且编码字节稳定

#### Scenario: 石砖掉落物可往返
- **GIVEN** 一个有效的石砖掉落物 upsert 消息
- **WHEN** 消息经过 v6 编码再解码
- **THEN** 解码结果保留相同 ID、石砖物品、数量和位置

#### Scenario: 非法掉落物负载被拒绝
- **GIVEN** 一个截断、含尾随字节、重复 ID、乱序 ID、非法物品数量或超限批次的掉落物消息
- **WHEN** v6 解码器处理该消息
- **THEN** 解码器 MUST 返回错误且不得 panic、分配无界内存或输出部分消息

#### Scenario: v5 客户端被拒绝
- **GIVEN** 客户端在握手中声明协议 v5
- **WHEN** 它连接 v6 服务端
- **THEN** 服务端在进入 Play 前返回稳定的不兼容版本结果并关闭登录流
