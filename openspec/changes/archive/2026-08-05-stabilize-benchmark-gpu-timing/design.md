## Context

动机与实测数据见 `proposal.md`。当前 `measureGPUCompletion` 对 2048 次「编码 → 提交 → `Poll(true)`」逐次计时，每个样本进入固定容量的 `client.LatencyRecorder`。`internal/gfx` 目前只暴露 `Submit` 与 `Poll`。本机适配器虽然报告支持 `FeatureNameTimestampQuery`，但所用绑定没有暴露任何写入时间戳的入口，该 feature 无法被利用。

## Goals / Non-Goals

**Goals:**

- 让 `remote_gpu_complete` 反映远端角色与昵称的真实绘制成本，且相对离散度远小于 `20%` 判定阈值。
- 让性能门禁只在指标分辨率足够时才施加相对回归判定。
- 降低 benchmark 的持续热负载，并让 GPU 采样不发生在刚结束的满载尾部。
- 保持既有 workload 结构、样本数、分辨率与绝对门禁不变。

**Non-Goals:**

- 不引入通用 GPU profiling 框架、逐 pass 计时或火焰图。
- 不改变 still/flying 的时长、相机脚本或帧时间统计口径。
- 不更换或 fork 图形绑定以获得时间戳写入入口。

## Decisions

### 1. 用批量分摊替代逐次 `Poll` 计时

一个样本不再是「一次提交到 `Poll` 返回」，而是「一批 `K` 次远端角色与昵称绘制编码进同一个 command buffer，提交后只 `Poll` 一次」的总耗时除以 `K`。`Poll` 的固定节拍在一个样本内只出现一次，被摊薄为 `节拍 / K`。

实测（Apple M5，2560x1440 离屏，7 个远端角色）：

| K | 总 p50 | 每次摊薄 | p95/p50 | p99/p50 |
|---|---|---|---|---|
| 1 | 1.288ms | 1.2882ms | 1.976 | 1.979 |
| 64 | 4.040ms | 0.0631ms | 1.614 | 1.885 |
| 256 | 15.038ms | 0.0587ms | 1.410 | 1.413 |
| 1024 | 62.725ms | 0.0613ms | 1.079 | 1.143 |

`K=1` 时 p95 恰好是 p50 的两倍，即纯粹的节拍量化；`K>=64` 后每次摊薄成本稳定在约 `0.06ms`，说明批量确实提取出了绘制信号。取 `K=1024` 时相对离散度降到 `+7.9%`（p95）与 `+14.3%`（p99），落在 `20%` 判定阈值以内。

否决 GPU 时间戳查询：当前绑定没有暴露任何写入时间戳的入口，查询集合无法填充；为此更换或 fork 图形绑定的代价远超收益。

否决继续逐次计时并加大单次绘制量：实测 64 次 clear 仍被量化到 `1.28ms` 的整数倍，只是把跳变搬到更高倍数。

### 2. 相对门禁只作用于分辨率足够的指标

`perfcheck` 对每个受检指标显式区分「可做相对回归判定」与「只做绝对上限判定」。判定依据是指标的测量分辨率是否远细于 `20%` 阈值。改用批量分摊后 `remote_gpu_complete` 重新具备足够分辨率，因此仍保留相对判定；本决策的作用是把这条规则写进门禁，使今后任何量化指标不会再被误配相对阈值。

绝对上限保持现值，不放宽。

### 3. 阶段之间加入冷却窗口

在预热与 still 之间、still 与 flying 之间、flying 与 GPU 采样之间各插入一段固定冷却等待，期间不提交渲染工作。冷却只影响阶段之间的时间轴，不改变任何被采集的量；报告中记录冷却时长以便复现。

否决降低帧率上限：still/flying 的帧时间分位数是核心指标，限帧会把它们变成上限周期本身，直接破坏测量。

### 4. scenario v12 与迁移

GPU 指标语义改变、阶段时间轴改变，因此 producer 标记 scenario v12，比较器只保留唯一显式 `11:12` 迁移，`10:11` 退役。历史 v6–v11 报告继续按各自规则读取。

### 5. 与 M4G 的先后关系

M4G 的 v11 候选保持冻结，不因本 change 重跑或改写。本 change 完成并建立 M5 scenario v12 基线后，M4G 再继续其归档流程；M4G 的 v11 正式链失败报告只保留为诊断证据。

## Risks / Trade-offs

- [批量分摊得到的是每次绘制的平均成本，单次尖峰被平滑] → 单次尖峰本来就无法与 `1.28ms` 节拍区分；提交侧的逐次开销由既有的 avatar/name tag submit 指标覆盖。
- [样本定义改变使 `remote_gpu_complete` 与历史 v6-v11 数值不可直接对比] → 这正是 scenario 升级要表达的；历史报告仍可按各自场景读取。
- [冷却窗口拉长总时长] → 以时间换可重复性与更低热负载；时长写入报告并记入基线证据。
- [又一次 scenario 升级需要重建基线] → 与 M4G 的 v11 基线合并为一次 v12 正式链，避免连续两次基线重建。

## Migration Plan

1. 先改探针为批量分摊并补齐测试，确认无窗口路径可用且指标携带绘制信号。
2. 改门禁的判定类型，更新 producer 为 v12 并退役 `10:11`。
3. 加入冷却窗口并更新文档。
4. 完成全仓门禁并冻结候选，取得一次性授权后执行 v12 正式链（Memory 一次、TCP 一次）。
5. 提升 M5 基线为 v12，然后回到 M4G 完成其归档。
