## MODIFIED Requirements

### Requirement: 掉落物按确定时序拾取和过期
新掉落物 SHALL 在生成 10 个活动模拟 tick 后才可拾取，并在累计 6000 个活动模拟 tick 后过期；仅当所属区块位于至少一名 Ready 玩家同维度、区块半径 2 的掉落物兴趣范围内时，年龄和拾取延迟才前进。每个活动 tick 中，服务端 MUST 按稳定玩家顺序和稳定掉落物 ID 顺序，让距离方块中心不超过 1.25 格的 Ready 玩家依次使用快捷栏和背包的稳定规则尽量接收可拾取物品。

#### Scenario: 拾取延迟结束前不拾取
- **GIVEN** Ready 玩家站在一个刚生成掉落物的拾取范围内
- **WHEN** 该掉落物尚未累计 10 个活动模拟 tick
- **THEN** 玩家完整物品状态和掉落物数量都保持不变

#### Scenario: 快捷栏不足时继续放入背包
- **GIVEN** 一个可拾取堆有 5 个石头，范围内首位玩家的快捷栏只能再接收 2 个且背包能接收其余 3 个
- **WHEN** 服务端处理该活动 tick
- **THEN** 快捷栏增加 2 个石头、背包增加 3 个石头且掉落物被移除

#### Scenario: 部分拾取保留余量
- **GIVEN** 一个可拾取堆有 5 个石头，范围内首位玩家的快捷栏与背包合计只能再接收 3 个
- **WHEN** 服务端处理该活动 tick
- **THEN** 玩家完整物品状态增加 3 个石头且原掉落物以相同 ID 保留 2 个石头

#### Scenario: 同 tick 竞争只有一次归属
- **GIVEN** 两名 Ready 玩家在同一可拾取堆范围内且都能通过快捷栏或背包接收全部物品
- **WHEN** 服务端处理该活动 tick
- **THEN** 稳定顺序靠前的玩家获得该堆且另一名玩家不获得重复物品

#### Scenario: 全满玩家不移除掉落物
- **GIVEN** 范围内玩家的快捷栏和背包都没有空间接收可拾取堆
- **WHEN** 服务端处理该活动 tick
- **THEN** 玩家完整物品状态和掉落物数量都保持不变

#### Scenario: 到达寿命后移除
- **GIVEN** 一个掉落物已累计 5999 个活动模拟 tick
- **WHEN** 所属区块再处理一个活动模拟 tick 且该堆没有被拾取
- **THEN** 服务端移除该掉落物且不向任何玩家物品状态添加物品

#### Scenario: 无观察者时寿命暂停
- **GIVEN** 一个掉落物所属区块不在任何 Ready 玩家同维度、区块半径 2 的兴趣范围内
- **WHEN** 服务端推进任意数量的其他世界 tick
- **THEN** 该掉落物的年龄和拾取延迟保持不变

### Requirement: 掉落物协议版本有界且不降级
线上协议 SHALL 升级为 v5，并继续为掉落物 upsert 和 remove 使用固定字段及显式上限；v4 或其他不匹配版本 MUST 在登录前稳定拒绝，不提供版本协商或降级解码。掉落物消息解码 MUST 拒绝截断、尾随字节、未知枚举、非法数量、越界位置、重复或乱序 ID 和超过 32 项的批次。

#### Scenario: v5 掉落物消息确定性往返
- **GIVEN** 任一有效且按稳定 ID 排序的掉落物 upsert 或 remove 消息
- **WHEN** 消息经过 v5 编码再解码
- **THEN** 解码结果与原值相同且编码字节稳定

#### Scenario: 非法掉落物负载被拒绝
- **GIVEN** 一个截断、含尾随字节、重复 ID、乱序 ID、非法物品数量或超限批次的掉落物消息
- **WHEN** v5 解码器处理该消息
- **THEN** 解码器 MUST 返回错误且不得 panic、分配无界内存或输出部分消息

#### Scenario: v4 客户端被拒绝
- **GIVEN** 客户端在握手中声明协议 v4
- **WHEN** 它连接 v5 服务端
- **THEN** 服务端在进入 Play 前返回稳定的不兼容版本结果并关闭登录流
