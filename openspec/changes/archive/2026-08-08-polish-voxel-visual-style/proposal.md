## Why

现有方块虽有确定性的程序化噪声，HUD 也已覆盖快捷栏、背包、生命值、合成、熔炉和箱子，但它们主要以平面色块直接呈现：方块种类辨识度有限，HUD 缺少统一边界与层级，生命值尤其与底部物品栏脱节。现在需要在不引入版权素材、依赖或第二套 UI 管线的前提下，把已有功能收敛为统一、清晰的体素视觉语言。

## What Changes

- 优化现有 16×16 程序化方块材质，以稳定的像素级图案强化草方块、石砖、矿石、熔炉、铁块和箱子等方块的辨识度，同时保留确定性和相邻纹理无缝采样。
- 复用现有 HUD quad、字形图集、物品色与布局机制，为快捷栏、背包、合成、熔炉和箱子统一深色边框、分组表面、选中/来源高亮和状态色。
- 可放置方块在快捷栏、背包、合成和容器栏位中复用注册表的真实程序化方块材质缩略图；非方块物品继续使用现有程序化色块。
- 把生命值改为固定在屏幕左下角、没有面板背景的一排十颗程序化像素爱心，每颗表示两点生命，并继续只显示服务端确认值。
- 优化栏位数量数字：单件物品不显示冗余数字，其余数量以右下对齐的深色像素阴影和暖白前景保持材质上的对比度；两位数量收紧字间距，避免字体 advance 留白造成视觉割裂。
- 保持固定容量、零分配热路径、现有命中几何和不同 framebuffer 尺寸下的可读性。
- 更新受影响的无窗口视觉 golden，并保留程序化材质与 HUD CPU 布局测试。
- 非目标：不改变游戏规则、协议、存档、服务端权威边界、输入语义、材质尺寸或渲染架构；不增加 UI 框架、依赖、shader pipeline 或手工绘制的二进制美术资源。

## Capabilities

### New Capabilities

- `voxel-visual-presentation`: 定义程序化方块材质与 HUD 的统一可观察视觉表现、状态反馈和尺寸适配要求。

### Modified Capabilities

- `visual-verification`: 更新视觉基线必须覆盖优化后的地形方块与 HUD 呈现，同时沿用无窗口、固定场景的验证路径。

## Impact

- 代码：`internal/assets` 的程序化方块材质生成与测试；`internal/render/hotbar.go`、HUD shader 及其布局测试；应用构造时把同一方块注册表交给 HUD。
- 验证：既有三个固定场景随程序化材质更新，并追加打开背包的固定场景；不自动启动或聚焦前台窗口。
- 兼容性：协议、玩家/区块存档与世界 metadata 不变；单机和 TCP 行为不变。
- 并发与性能：不增加 goroutine、每帧分配、动态容量、额外 render pass 或 draw；初始化时只生成一张复用注册表像素的小型 HUD 图集，现有固定 HUD 上传上限保持有界。
- 依赖与资产：不新增依赖，不加入 Mojang 或其他未经授权的二进制美术资源。
