# 局域网专用服务端

`mcgod` 是无渲染 TCP 专用服务端。`--max-players` 只接受 `1..8`，默认 8。启动一个新世界或打开已有世界：

```sh
go run ./cmd/mcgod --listen :25565 --world worlds/lan --seed 42 --max-players 8
```

同一局域网中的客户端可连接服务器所在机器的私有地址：

```sh
go run ./cmd/mcgo --connect 192.168.x.x:25565 --name Chen
```

如果只允许本机连接，请明确监听 loopback 地址：

```sh
go run ./cmd/mcgod --listen 127.0.0.1:25565 --world worlds/local --max-players 8
```

两个客户端人工验收时，在两个终端分别执行：

```sh
go run ./cmd/mcgo --connect 127.0.0.1:25565 --name 星河
go run ./cmd/mcgo --connect 127.0.0.1:25565 --name 月海
```

客户端首次运行会在本机 profile 中创建稳定 UUIDv4；之后改变 `--name` 只更新这个 ID 的显示名，不会创建新玩家。相同 PlayerID 同时登录会被拒绝；不同 PlayerID 可使用相同显示名，因此昵称不是身份凭据，也不保证唯一。

客户端正常断线后，服务端会保存该玩家的最终位置、安全位置以及完整 36 格物品状态（含选中栏位及工具剩余耐久）；随后使用同一 PlayerID 重连会恢复存档。物品状态是每名玩家私有的，只发送给所属会话，不会广播给其他玩家。按 `Ctrl-C` 或发送 SIGTERM 正常关服时，服务端先停止接纳连接，再按客户端优先顺序断开会话，并刷写玩家与区块存档。不要通过强制杀进程来替代正常关服。

按 `Ctrl-C`（SIGINT）或向进程发送 SIGTERM 可正常关闭服务端。它会停止接纳连接、刷写玩家和区块存档并释放 `world.lock`。备份前请先执行上述正常关服步骤，等待进程退出后再复制整个世界目录；不要在服务端运行时复制存档文件。

掉落物：挖掘会在原地留下掉落物，而不是直接进入快捷栏。掉落物属于所属区块，每区块最多 32 堆，随该区块在同一条记录中原子存档；每名玩家只会收到自己脚下区块半径 2 内的掉落物，单人镜像上限 800 堆，因此慢连接只影响它自己。

背包与合成：每名玩家有固定 9 格快捷栏加 27 格背包共 36 格权威物品状态，只发送给所属连接。可用镐与对应损坏物品每格最多一个，其他当前物品每格最多 64 个。客户端用 `E` 打开界面、两次左键整堆移动；客户端不预先扣料或增加产物，服务端从当前权威状态原子执行并回传完整状态。固定配方表与图形背包都显示 `4 石头 → 4 石砖`、`8 石头 → 1 熔炉`、`8 石头 → 1 箱子`、`9 铁锭 → 1 铁块`、`3 石头 → 1 石镐`、`3 铁锭 → 1 铁镐`，新合成的镐为满耐久。普通背包开关不是服务端状态，界面打开期间世界与 tick 继续推进。

矿石与熔炉：新生成石头中，煤矿只在 `Y < 96` 以约 `1/2048` 出现，铁矿只在 `Y < 48` 以约 `1/4096` 出现，铁矿优先；已保存区块不批量改写。客户端对准六格内熔炉右键只发打开意图，服务端重新射线验证后才建立查看关系。界面的 `0..35` 是玩家物品，36/37/38 分别是粗铁输入、煤炭燃料和铁锭输出；输出格只能作为来源。一个煤炭提供 1600 燃烧 tick，每个铁锭需要 200 进度 tick；条件无效时两者同时暂停。熔炉是区块共享状态，每区块最多 32 个，多名查看者会收到同一最终状态。熔炉与箱子共用同一套查看生命周期：每名玩家同时只能查看一个容器，打开另一个会结束当前查看关系。

箱子：服务端固定配方 `8 石头 → 1 箱子`，箱子可放置、可挖掘，挖掘桶与熔炉相同（裸手/普通物品 `30` tick、石镐 `15` tick、铁镐 `8` tick，至少石镐才能取得掉落）。每个区块最多同时存在 16 个活动箱子，每个箱子固定 27 格，接受任何已注册物品（含带耐久的工具）；放满 16 个后再放置会被原子拒绝且不消耗玩家物品。对准已放置的箱子右键，收到服务端确认后会打开统一 `0..62` 栏位界面：`0..35` 是玩家物品，`36..62` 是箱子的 27 个格子，移动语义同背包/熔炉，两次左键点击整堆移动。破坏箱子前服务端会在掉落物副本上按箱子本体、再按 `36..62` 顺序预演全部非空格，只有全部堆都能完整放入所属区块的掉落物槽时才清除方块、停用槽位并一次性提交，容量不足时方块、箱子内容与掉落物都保持不变。图形背包的固定合成面板有石砖、熔炉、铁块、石镐、铁镐和箱子六个可点击入口，箱子可以直接在界面里合成。本批不支持大箱子合并、命名、排序、快捷搬运、拆分堆、漏斗、比较器、潜行放置或任何自动化。

权威采掘：客户端按住左键时只发送持续意图，服务端每个 20 Hz tick 按权威位置、视角、当前工具和六格射线推进每名玩家自己的进度。固定时长与掉落为：泥土/草任意手持均 `5` tick 且掉落；石头为空手/普通物品 `30`、石镐 `15`、铁镐 `8` tick，但普通物品完成后不掉落；石砖/熔炉/箱子/煤矿/铁矿为 `30/15/8` tick，至少石镐才掉落；铁块为 `40/20/10` tick，仅铁镐掉落；基岩不推进。松键、换目标、换方块、换工具、超距、打开容器、断线或 reset 都会清零；各玩家进度不共享。错误工具破坏熔炉时不掉熔炉本体，但内部物品仍原子保全。

工具耐久：石镐最大耐久为 `131`，铁镐为 `250`。成功且实际破坏方块会扣除所持工具恰好 1 点耐久，与是否达到掉落等级无关；受保护方块、区块未就绪和掉落物容量已满三条拒绝路径不扣耐久。最后一点仍完成本次破坏和应有掉落，随后转为对应损坏物品。损坏物品采掘时等同空手，可以保留、移动或丢弃，但不能合成、熔炼、修复或回收；当前没有补耐久途径。快捷栏只为磨损中且仍可用的工具显示耐久条，满耐久工具、普通物品和损坏形态不显示。

版本与存档兼容性：服务端和客户端必须成套升级。线上协议为 v12；v11 及所有其他不匹配版本会在握手阶段、进入 Play 前被稳定拒绝，不提供版本协商或降级解码。容器消息在 v12 中改用容器中性命名（`OpenContainer`/`MoveContainerStack`/`CloseContainer`/`ContainerClosed`）但保留原有 packet ID，并新增固定长度的 `ChestState`；既有 packet ID 不重排，已废止的 Play client packet ID `1` 继续保持未分配。世界 metadata 保持 v2 并持久化绝对世界时间；玩家存档保持 schema v4 不变；区块存档从 schema v5 升级为 schema v6，在熔炉之后追加固定 16 个箱子槽；v6 程序可无损迁移 v1–v5 的历史区块，只认识 v5 及更早的旧程序遇到 v6 区块会按未来 schema 稳定拒绝；benchmark scenario 保持 v12，箱子由玩家放置，固定种子的 benchmark 世界中不出现任何箱子。读取旧 schema v3 玩家档时旧工具迁移为满耐久；写回新格式后，v11 程序不能读取已升级的区块存档。**备份与回退**：升级前必须正常关服，等待进程退出后备份整个世界目录，再启动 v12 程序完成首次写入；一旦区块被写为 schema v6，只认识 v5 及更早的旧程序无法再打开该世界。回退时必须先停止服务，再用升级前的完整备份整体恢复世界目录，不能让旧程序直接读取已经升级的目录。异常进程退出时玩家文件与区块文件各自原子，但两者之间没有跨文件事务：崩溃可能只保留其中一侧的最新提交。

当前尚无工具修复或损坏物品回收、木材资源链、多原料合成、多人共享采掘进度和裂纹贴图；箱子尚不支持大箱子合并、命名、排序、快捷搬运、拆分堆、漏斗、比较器、潜行放置或任何自动化。

> 安全警告：当前 TCP 没有认证，也没有加密。PlayerID 与昵称都由客户端声明，任何能连到监听地址的人都可尝试冒用身份或读取/篡改明文流量。仅可用于可信局域网；不要在路由器上做端口映射，也不要暴露到公网。
