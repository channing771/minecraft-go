# 局域网专用服务端

`mornlea-server` 是无渲染 TCP 专用服务端。`--max-players` 只接受 `1..8`，默认 8。启动一个新世界或打开已有世界：

```sh
go run ./cmd/mornlea-server --listen :25565 --world worlds/lan --seed 42 --max-players 8
```

同一局域网中的客户端可连接服务器所在机器的私有地址：

```sh
go run ./cmd/mornlea --connect 192.168.x.x:25565 --name Chen
```

如果只允许本机连接，请明确监听 loopback 地址：

```sh
go run ./cmd/mornlea-server --listen 127.0.0.1:25565 --world worlds/local --max-players 8
```

两个客户端人工验收时，在两个终端分别执行：

```sh
go run ./cmd/mornlea --connect 127.0.0.1:25565 --name 星河
go run ./cmd/mornlea --connect 127.0.0.1:25565 --name 月海
```

客户端首次运行会在本机 profile 中创建稳定 UUIDv4；之后改变 `--name` 只更新这个 ID 的显示名，不会创建新玩家。相同 PlayerID 同时登录会被拒绝；不同 PlayerID 可使用相同显示名，因此昵称不是身份凭据，也不保证唯一。

客户端正常断线后，服务端会保存该玩家的最终位置、安全位置、生命值以及完整 36 格物品状态（含选中栏位及工具剩余耐久）；随后使用同一 PlayerID 重连会恢复存档。物品状态是每名玩家私有的，只发送给所属会话，不会广播给其他玩家。按 `Ctrl-C` 或发送 SIGTERM 正常关服时，服务端先停止接纳连接，再按客户端优先顺序断开会话，并刷写玩家与区块存档。不要通过强制杀进程来替代正常关服。

按 `Ctrl-C`（SIGINT）或向进程发送 SIGTERM 可正常关闭服务端。它会停止接纳连接、刷写玩家和区块存档并释放 `world.lock`。备份前请先执行上述正常关服步骤，等待进程退出后再复制整个世界目录；不要在服务端运行时复制存档文件。

掉落物：挖掘会在原地留下掉落物，而不是直接进入快捷栏。掉落物属于所属区块，每区块最多 32 堆，随该区块在同一条记录中原子存档；每名玩家只会收到自己脚下区块半径 2 内的掉落物，单人镜像上限 800 堆，因此慢连接只影响它自己。

背包与合成：每名玩家有固定 9 格快捷栏加 27 格背包共 36 格权威物品状态，只发送给所属连接。可用镐与对应损坏物品每格最多一个，其他当前物品每格最多 64 个。客户端用 `E` 打开界面、两次左键整堆移动；客户端不预先扣料或增加产物，服务端从当前权威状态原子执行并回传完整状态。固定配方表与图形背包都显示 `4 石头 → 4 石砖`、`8 石头 → 1 熔炉`、`9 铁锭 → 1 铁块`、`3 石头 → 1 石镐`、`3 铁锭 → 1 铁镐`、`8 石头 → 1 箱子`、`1 橡木原木 → 4 橡木木板`、`4 玻璃 → 4 发光方块`，新合成的镐为满耐久。普通背包开关不是服务端状态，界面打开期间世界与 tick 继续推进。

静态方块光：客户端只从已接受的权威方块镜像派生传播天空光和静态方块光，服务端不计算、保存或传输光照数组。发光块可按普通完整方块放置，也可用石镐或铁镐挖回；有固定配方（`4 玻璃 → 4 发光方块`），但尚无初始发放、世界生成或管理命令等其他获取入口。

常见材料：圆石、平滑石、沙子、砾石、橡木原木、橡木木板、树叶、玻璃、砖块、白色羊毛、红色瓦块、黏土、雪块和苔藓圆石均由服务端权威放置、采掘并掉落自身。只有存档缺失的新玩家会在背包前 14 格依次各获得 64 个材料；已有玩家、迁移玩家与未确认登录都不会补发或累加。玻璃和树叶保持完整方块碰撞，以单 pass alpha cutout 呈现且不完全遮挡客户端派生光照。沙子、砾石、黏土、雪块会按种子在新生成区块自然出现，橡树确定性生成橡木原木与树叶；旧世界可停服后运行 `mornlea-server --world <世界目录> --migrate-materials --backup <备份目录>` 离线迁移到同一套自然材料规则，迁移只重算石头、泥土、草、沙子、砾石、黏土和雪块七种自然值，其余状态保持不变。

矿石与熔炉：新生成石头中，煤矿只在 `Y < 96` 以约 `1/2048` 出现，铁矿只在 `Y < 48` 以约 `1/4096` 出现，铁矿优先；已保存区块不批量改写。客户端对准六格内熔炉右键只发打开意图，服务端重新射线验证后才建立查看关系。界面的 `0..35` 是玩家物品，36/37/38 分别是原料输入、煤炭燃料和产物输出；输出格只能作为来源。熔炼固定三条映射：粗铁→铁锭、沙子→玻璃、黏土块→砖块，输入种类切换时清零进度并保留燃烧时间。一个煤炭提供 1600 燃烧 tick，每个产物需要 200 进度 tick；输入无效或输出已满时进度与燃料同时暂停。熔炉是区块共享状态，每区块最多 32 个，多名查看者会收到同一最终状态。熔炉与箱子共用同一套查看生命周期：每名玩家同时只能查看一个容器，打开另一个会结束当前查看关系。

箱子：服务端固定配方 `8 石头 → 1 箱子`，箱子可放置、可挖掘，挖掘耗时与熔炉相同（裸手/普通物品 `30` tick、石镐 `15` tick、铁镐 `8` tick，至少石镐才能取得掉落）。每个区块最多同时存在 16 个活动箱子，每个箱子固定 27 格，接受任何已注册物品（含带耐久的工具）；放满 16 个后再放置会被原子拒绝且不消耗玩家物品。对准已放置的箱子右键，收到服务端确认后会打开统一 `0..62` 栏位界面：`0..35` 是玩家物品，`36..62` 是箱子的 27 个格子，移动语义同背包/熔炉，两次左键点击整堆移动。破坏箱子前服务端会在掉落物副本上按箱子本体、再按 `36..62` 顺序预演全部非空格，只有全部堆都能完整放入所属区块的掉落物槽时才清除方块、停用槽位并一次性提交，容量不足时方块、箱子内容与掉落物都保持不变。图形背包的固定合成面板有石砖、熔炉、铁块、石镐、铁镐、箱子、橡木木板和发光方块八个可点击入口，箱子可以直接在界面里合成。本批不支持大箱子合并、命名、排序、快捷搬运、拆分堆、漏斗、比较器、潜行放置或任何自动化。

权威采掘：客户端按住左键时只发送持续意图，服务端每个 20 Hz tick 按权威位置、视角、当前工具和六格射线推进每名玩家自己的进度。固定时长与掉落为：泥土/草任意手持均 `5` tick 且掉落；石头为空手/普通物品 `30`、石镐 `15`、铁镐 `8` tick，但普通物品完成后不掉落；石砖/熔炉/箱子/发光块/煤矿/铁矿为 `30/15/8` tick，至少石镐才掉落；铁块为 `40/20/10` tick，仅铁镐掉落；基岩不推进。松键、换目标、换方块、换工具、超距、打开容器、断线或 reset 都会清零；各玩家进度不共享。错误工具破坏熔炉时不掉熔炉本体，但内部物品仍原子保全。

工具耐久：石镐最大耐久为 `131`，铁镐为 `250`。成功且实际破坏方块会扣除所持工具恰好 1 点耐久，与是否达到掉落等级无关；受保护方块、区块未就绪和掉落物容量已满三条拒绝路径不扣耐久。最后一点仍完成本次破坏和应有掉落，随后转为对应损坏物品。损坏物品采掘时等同空手，可以保留、移动或丢弃，但不能合成、熔炼、修复或回收；当前没有补耐久途径。快捷栏只为磨损中且仍可用的工具显示耐久条，满耐久工具、普通物品和损坏形态不显示。

权威生命值与死亡：每名玩家的生命值由服务端唯一权威，满值为 20（`0..20`），随权威玩家状态私下发布给所属连接，跨重连和重启持久化；客户端只显示服务端确认值，HUD 在左上角画一个背景色块加当前数字，不做任何预测。摔落安全高度 3 格：系统在"上一 tick 不在地面、这一 tick 在地面"的边沿按 `伤害 = floor(下落高度) − 3` 结算一次伤害，负值不扣血，例如 4 格摔落扣 1 点、满血玩家从 23 格摔落会摔死；跳跃、平地行走和落地后停留都不扣血，传送/重生/维度 reset 会重置摔落峰值。未受伤连续 `100` tick 后进入自动回复，此后每 `40` tick 回 1 点直到满值，任何伤害都会清零计时并中断回复。生命值降到 0 时，服务端在同一 tick 内把玩家 36 个物品栏格逐格掉进世界（放置成功才清空该格，物品不销毁）、传回出生锚点、回满血、速度归零；掉落物从死亡区块按半径 0、1、2… 环形外扩只写入已加载且 Ready 的区块，扫完仍放不下的格保留在背包里跟随重生；外部观察不到生命值为 0 的中间状态。当前没有战斗、PvP、怪物、食物与饥饿，也没有溺水、窒息、岩浆、火焰等其他伤害源，也没有床或自定义重生点、伤害动画音效和专门的死亡界面。

版本与存档兼容性：服务端和客户端必须成套升级。线上协议为 v15；v14 及所有其他不匹配版本会在握手阶段、进入 Play 前被稳定拒绝，不提供版本协商或降级解码。v14→v15 只追加稳定方块与物品语义，packet ID、payload 长度和字段布局保持不变；已废止的 Play client packet ID `1` 继续保持未分配。世界 metadata 保持 v2，玩家存档写为 schema v6，v5→v6 identity migration 不补发材料；区块存档写为 schema v8，含静态发光块的 v7 区块读取后按原 payload 语义迁移。benchmark scenario 为 v15；M2 当前基线是 Memory v15，TCP v15 独立记录，M2 v6 保留历史身份，M5 当前基线仍为 v14 并等待未来同硬件 `14:15` 迁移。**备份与回退**：升级前必须正常关服，等待进程退出后备份整个世界目录，再启动 v15 程序；回退时必须先停服并恢复升级前的完整备份，不承诺把 schema v8 区块、schema v6 玩家档或新物品降级写回，也不能让旧程序直接打开已升级目录后继续写入。异常退出时玩家文件与区块文件各自原子，但两者之间没有跨文件事务。

当前尚无工具修复或损坏物品回收、更完整的木材加工链、多原料合成、多人共享采掘进度和裂纹贴图；箱子尚不支持大箱子合并、命名、排序、快捷搬运、拆分堆、漏斗、比较器、潜行放置或任何自动化；生命值只对摔落生效，尚无战斗、怪物、食物、其他伤害源、床与重生点设置。

> 安全警告：当前 TCP 没有认证，也没有加密。PlayerID 与昵称都由客户端声明，任何能连到监听地址的人都可尝试冒用身份或读取/篡改明文流量。仅可用于可信局域网；不要在路由器上做端口映射，也不要暴露到公网。
