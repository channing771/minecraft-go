**状态：** 已确认

## 1. 背景

上一批已经交付常见块状材料、自然沙石黏土雪、材料加工闭环和目标方块反馈。下一批继续补建造与世界表现，同时修复上一轮评审确认的存储校验缺陷。四项工作必须能在四个独立 worktree 中并行实现、验证和评审；不得为了并行而引入共享脚手架或通用框架。

本批包含：

1. 修复熔炉与箱子存档校验误用 section-local Y；
2. 使用现有橡木原木与树叶生成确定性橡树；
3. 为发光方块增加正常固定合成入口；
4. 在现有天空 pass 中增加程序化方块云层。

横向原木与薄雪层需要共享的方块状态、协议和存档编码，容易与本批存储修复形成高冲突，因此不纳入本批。水体、天气状态、云实体、配方分页和通用世界结构框架也不在范围内。

四项工作分别建立独立 OpenSpec change、分支和 worktree：

## 3. 任务一：容器世界 Y 修复

### 3.1 根因

`world.BlockPosFromChunkIndex` 已把区块内紧凑索引还原为世界坐标。当前 `validateFurnaceSlots` 与 `validateChestSlots` 随后调用 `pos.Local()` 并把其中的局部 Y 传给要求世界 Y 的 `Chunk.BlockAt`。当容器不在恰好同余的世界高度时，合法槽会被误判为没有指向熔炉或箱子。

### 3.2 最小修复

两条校验路径只从 `pos.Local()` 取局部 X/Z，读取方块时直接使用 `pos.Y`。现有索引范围、重复索引、槽状态和对应方块类型校验全部保留。无需新增 helper、接口或迁移层。

### 3.3 兼容性与失败语义

修复不改变 chunk schema v8、协议 v15、磁盘字节或索引定义。已有数据未被错误编码，只是在读取或保存校验时被误拒绝。修复后合法高层容器恢复可读；越界、重复或指向错误方块的记录仍返回 `ErrCorrupt`，不得降级接受。

## 4. 任务二：确定性橡树

### 4.1 生成规则

世界按 `8×8` 水平网格划分。每个网格由世界种子与网格坐标哈希出一个候选根位置，并以固定 50% 概率决定是否成树。候选位置的最终自然地表必须是草方块，树体最高点必须低于 `core.MaxY`；因此沙地、雪地和无有效上方空间的位置不生成树。

树干从地表上方开始，高度由同一哈希稳定选择 `4..6` 格。树冠采用已确认的紧凑自然轮廓：约 `5×5`，分层包围树顶，并由固定哈希移除部分边角。所有随机选择只依赖世界种子和世界坐标，不得依赖区块加载、查询或生成顺序。

### 4.2 单点与整区块一致性

树候选和树体占用判断是无内部状态的纯逻辑。`BaseBlockAt` 查询目标位置附近可能覆盖它的候选树；`GenerateChunk` 枚举可能跨入目标区块的相邻网格并应用同一树形规则。负坐标必须使用向负无穷一致的网格划分。

树块只覆盖原始空气；树叶不得覆盖既有实心自然地形。多个树冠重叠时原木优先于树叶，结果必须与候选遍历顺序无关。树冠可以跨区块边界，边界两侧分别生成后必须无接缝。

### 4.3 兼容性

复用现有 `OakLogID` 与 `LeavesID`，不新增方块、物品、协议字段或存档字段。已经保存的区块保持原样；尚未生成或未保存的区块按新生成器产生橡树。本批不提供旧世界树木迁移命令。

## 5. 任务三：发光方块固定配方

### 5.1 权威配方

在现有稳定配方末尾追加 recipe ID `8`：消耗 `4` 个 `ItemGlass`，产出 `4` 个 `ItemLightBlock`。继续复用 `core.Inventory.Craft` 的完整物品状态副本、统一栏位扣料、完整产物插入和原子提交。原料不足、产物放不下、物品状态非法或配方未知时必须保持原物品状态不变。

客户端仍只发送 sequence 与 recipe ID；服务端定义原料、数量和产物。Memory 与 TCP 必须得到相同确认和持久化结果。现有 wire 能表达新 ID，发光方块物品也已属于当前玩家 schema，因此不升级协议、玩家 schema 或区块 schema。旧实现收到未知 ID `8` 时仍会安全拒绝。

### 5.2 HUD

固定配方面板保持单列，从 7 行扩为 8 行。`inventoryRecipeIDs`、固定 quad/glyph 容量、注释和 `openHUDHeight` 同步更新；现有 `hudScale` 在 640×360 等窄屏整体缩放完整 HUD。绘制与 `RecipeButtonAt` 继续共用相同几何，不增加两列布局、滚动、分页或可配置目录。

OpenSpec 必须同时更新 `authoritative-crafting`、`static-block-light` 与 `voxel-visual-presentation`，删除“发光方块没有获取入口”和旧固定配方数量的历史约束。

## 6. 任务四：程序化方块云

### 6.1 表现规则

云层使用已确认的稀疏云岛样式：固定世界高度 `Y=192`、`16×16` 方块单元、约 25% 覆盖，边缘保持方块台阶。相机世界坐标用于射线与云平面求交；权威世界时间派生云偏移，云以每 `80` tick 向东移动一格。所有客户端在相同世界时间和相机位置下必须得到相同云图案。

相机位于云层上方或视线不与云平面正向相交时不绘制云。接近地平线时以固定范围淡出，避免无限远采样混叠。云色随现有昼夜亮度变暗，并在最终天空颜色上覆盖其后的星星、太阳和月亮；不改变天体方向或权威昼夜计算。

### 6.2 渲染边界

继续复用现有 fullscreen sky pass 和 `sky.wgsl`。`render.Camera` 向天空 uniform 追加相机位置与由权威世界时间得到的云偏移；不增加纹理、采样器、云 mesh、GPU buffer、render pass 或 CPU 每帧分配。程序化哈希只在 fragment shader 中执行固定次数的有界运算。

云层实现可以与前三项并行开发，但视觉 golden 必须等前三项合入后再刷新。最终视觉结果必须继续由无窗口 capture 验证，不得启动或聚焦交互式客户端。

## 7. 错误处理与边界

- 存储校验继续把越界索引、重复索引、非法槽与错误方块引用视为损坏数据。
- 橡树生成遇到世界上界、非草地表或非空气占用时稳定跳过，不覆盖既有实心地形。
- 合成任何失败都不得部分扣料、部分产出或发布错误确认。
- 云射线没有有效交点时直接保留原天空颜色；shader、uniform 或 GPU 初始化错误继续沿用现有渲染错误路径，不增加静默 fallback。

## 8. 验证

### 8.1 各任务最小回归

- **存储：** 熔炉和箱子在底部、中部、顶部 section 的编码/解码；错误方块、越界与重复索引仍拒绝；恢复 local-Y 旧实现的 mutation 必须失败。
- **橡树：** 固定种子根位置、50% 门槛、`4..6` 树高、紧凑树冠、原木优先、负坐标、跨区块边界、`BaseBlockAt` 与 `GenerateChunk` 一致；新增无窗口 `oak-grove` 场景。
- **配方：** ID `8` 稳定映射、原子成功与失败、Memory/TCP 一致、8 行绘制与命中、640×360 无裁切；只更新 `inventory-crafting` 场景。
- **云层：** headless shader 测试覆盖固定图案、世界坐标视差、权威时间位移、覆盖率、昼夜色和天体遮盖；最终重跑全部无窗口视觉场景。

### 8.2 每个 worktree 的交付门禁

每项至少运行受影响包 `-race -count=1`、`go test ./internal/archcheck -count=1`、`go test ./... -race`、`go vet ./...`、`gofmt -l .`、`git diff --check` 与 `openspec validate --all --strict --no-interactive`。渲染和世界生成任务记录对应 benchmark；性能数值只记录，不改变退出状态。报告结构错误、真实 overflow、数据丢失、I/O 错误和测试失败仍是门禁。
