# 玩家预测展示连续性设计

日期：2026-07-29
状态：已实施

## 问题

前台交互测试显示：鼠标转向顺滑，但平移和跳跃有明显的不均匀感。移动与静止的原生
采样没有发现存档工作进入渲染或 tick goroutine；移动阶段增加的主要是预期内的视锥
和可见性计算。Task 17 的 `SaveObserver` 在 save worker 中于 `SaveBatch` 返回后执行，
不能合理解释仅发生在位置变化上的卡顿。

但客户端预测器会在一次完全正确的权威确认中制造展示位置不连续。和解前，展示位置
在 `previous` 与 `current` 之间插值。当服务端确认最后一个预测输入后，待重放历史可
变为空，`previous` 与 `current` 都被设为同一权威状态。此时 `current` 没变，所以
当前状态误差为零，现有纠正平滑被清空；然而插值后的展示位置会提前跳到 `current`。
在 20Hz 固定步下，这种重复跳变看起来像掉帧，即使相机旋转与渲染本身仍然顺滑。

## 范围

只修改客户端预测的展示连续性。不修改服务端 tick 率、权威物理、碰撞规则、网络协议、
存档、渲染或性能场景几何。重置、维度变化和大幅权威纠正继续保持现有立即跳转语义。

## 设计

`Predictor.ApplyPlayerState` 已经会在重建权威状态与未确认输入重放前捕获实际展示位置。
重建完成后，再把该位置与新的原始插值目标比较。

和解后的展示分为三种模式：

1. **仅插值基准变化或低于纠正阈值：** 最终预测位置误差低于 `1/128` 格，但重建
   `previous` 或历史改变了插值目标时，设置 `displayOffset`，使 ack 后第一帧与 ack
   前展示位置完全一致。偏移在以下两个时长的较大值内衰减：

   - 当前固定步的剩余时间；
   - 已在执行的纠正所剩时间。

   对普通的最后输入确认，在剩余固定步内衰减会精确补回历史重置抹掉的插值段，不新增
   一个 tick 的延迟，并在下一个固定步边界收敛。

2. **真实小幅纠正：** 最终预测误差位于 `[1/128, 0.5)` 格时，保留现有 100ms
   纠正衰减，并从 ack 前的实际展示位置开始。

3. **大幅纠正或重置：** 误差达到 `0.5` 格，或收到显式重置时，清空偏移并保持现有
   立即跳转行为。

若重建目标已经等于旧展示位置，则不创建新偏移。物理状态和输入历史仍完全服从权威；
偏移只影响展示。

## 数据流与不变量

1. 捕获 `oldDisplayed`、`oldPredicted` 和原纠正剩余时间。
2. 应用权威状态、删除已确认输入并重放剩余输入。
3. 计算最终当前状态误差和原始插值目标。
4. 选择上述三种模式之一。
5. `PresentationPosition(frameElapsed)` 继续单调消耗选定偏移；下一物理步仍只由
   `current`、输入和碰撞数据驱动。

必须保持：

- 完全正确的确认不会在 `ApplyPlayerState` 内改变展示位置；
- 普通移动和跳跃轨迹保持单调连续，不出现 20Hz 平台或跳变；
- 仅基准变化的连续性偏移在下一个固定步边界前收敛，除非它正在保留一个剩余时间更长
  的既有纠正；
- 小幅纠正仍恰好在 100ms 内完成；
- 大幅纠正、重置、非法状态拒绝、暂停和最终权威收敛保持原语义。

## 测试

实现前新增聚焦预测器测试：

- 在半步 accumulator 下确认唯一预测输入，权威状态与当前状态完全相同；确认后展示
  位置必须立即保持不变，并在剩余半步结束时到达 `current`；
- 以高频渲染间隔重复完全正确的确认，分别覆盖水平移动和跳跃；每个展示增量必须连续，
  且预测器最终收敛到权威状态；
- 既有小幅纠正正在衰减时收到完全正确的确认；不得重启或缩短剩余纠正；
- 保留现有 100ms 小幅纠正、0.5 格立即跳转、过期消息、重置、非法输入和延迟权威
  收敛测试。

聚焦测试需在 race 下重复运行，然后执行 `internal/client`、`cmd/mcgo`、全仓 race、
vet、gofmt 和 diff 检查。最后使用临时世界做前台移动/跳跃对照，并以可恢复方式清理
临时世界。
