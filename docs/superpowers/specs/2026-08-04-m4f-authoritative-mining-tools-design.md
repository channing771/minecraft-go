# M4F 权威工具与计时采掘设计

- 日期：2026-08-04
- 状态：已评审通过
- 范围：石镐、铁镐、服务端权威计时采掘、采掘等级与 HUD 进度

## 1. 背景与目标

M4E 已经形成矿石、合成和熔炼资源链，但采掘仍是一次点击立即破坏，煤矿、铁矿和铁块也没有工具门槛，铁资源除合成铁块外缺少进阶价值。

M4F 用最小闭环补上两级工具和权威计时采掘：玩家可由裸手取得石头并制作石镐，再用石镐采集矿石、熔炼铁锭并制作更快的铁镐。服务端决定目标、进度、工具等级、完成时机和掉落，客户端只发送持续输入并呈现权威状态。

本批不实现木材、木棍、木镐、多原料配方、工具耐久、裂纹贴图、多人共享采掘进度、经验、附魔或通用物品元数据。

## 2. 玩家可观察行为

新增两个不可放置、不可作为燃料且单格最多一个的物品：

- `3 石头 → 1 石镐`；
- `3 铁锭 → 1 铁镐`。

玩家按住左键持续采掘，HUD 在屏幕中心下方显示最后确认的权威进度。可以正常取得掉落时进度条为绿色；工具等级不足、完成后不会产生方块掉落时为橙色。

每名玩家只拥有一个独立采掘目标。松开左键、打开容器、换目标、换工具、超出六格距离、目标方块变化、区块不可用、断线或 session reset 时，进度立即清零。不同玩家不共享或累加进度。

### 2.1 首批采掘表

权威 tick 为 20 Hz，时长均为整数 tick：

| 方块类别 | 裸手或错误工具 | 石镐 | 铁镐 | 正常掉落要求 |
|---|---:|---:|---:|---|
| 土、草 | 5 | 5 | 5 | 无 |
| 石头 | 30 | 15 | 8 | 空选中格作为裸手启动例外，或任一镐 |
| 石砖、熔炉、煤矿、铁矿 | 30 | 15 | 8 | 至少石镐 |
| 铁块 | 40 | 20 | 10 | 铁镐 |
| 基岩 | 不推进 | 不推进 | 不推进 | 无 |

只有空选中格算裸手；手持普通方块或其他非工具物品不触发石头的启动掉落例外。工具等级不足时仍能完成破坏，但不产生方块本体或矿物掉落。熔炉内已有物品不是方块掉落，必须继续原子落地，避免因错误工具静默丢失玩家物品。

## 3. 方案选择

采用在现有 `PlayerInput` 中携带持续采掘状态的方案。客户端预测器已经按固定物理步发送该消息，服务端也已经以最后有效输入推进权威移动，因此增加一个布尔值即可同时获得按住、松开、移动和视角变化的有序状态。

否决新增开始/停止命令：它会增加独立生命周期、异常清理和边沿丢失后的恢复路径，而服务端仍需结合持续的玩家视角重新射线检测。

否决客户端计时后提交完成请求：它允许客户端声明完成时机，违背服务端权威边界，也无法可靠处理移动、工具切换和多人竞争。

## 4. 权威数据与 tick 顺序

`playerState` 增加一个固定大小的在途采掘值，记录是否活动、目标位置、开始时方块 ID、工具物品 ID、已完成 tick、总 tick 和是否可取得掉落。它不使用 map、slice、goroutine 或磁盘存档。

每个权威 tick 按以下顺序执行：

1. 按现有 session、sequence 顺序应用 `PlayerInput`、快捷栏选择和背包操作；同 tick 多份输入仍由最后有效值胜出。
2. 推进玩家权威物理与订阅中心。
3. 按 `SessionID` 升序处理最多八名活动玩家的采掘。
4. 从权威脚底位置加眼高、权威 yaw/pitch 做六格 DDA 射线，读取权威选中栏位和目标方块。
5. 输入未按住或目标无效时清零；目标、方块 ID 或工具物品变化时以当前状态重新开始并计为第一个 tick；其余情况递增一个 tick。
6. 达到总 tick 时复用方块破坏、掉落容量和熔炉原子批量掉落逻辑。成功或失败后均清零在途状态。
7. 完成区块 revision、物品、熔炉和掉落物提交后，随本 tick `PlayerState` 发布最终采掘状态。

若两名玩家在同一 tick 完成同一方块，较小 `SessionID` 先提交；后一名重新读取时看到空气并清零，不产生第二次掉落。

## 5. 物品与配方模型

在现有稳定枚举末尾追加石镐、铁镐和两条配方 ID，不重排任何旧编号。`core` 提供统一的物品堆叠上限查询：两把镐为 1，其余当前物品为 64。`ItemStack.Valid`、背包加堆、同类合并、拾取和合成必须使用同一上限，避免只在 UI 或单个入口阻止工具堆叠。

现有固定单输入、单输出 `CraftingRecipe` 足以表达两条配方，不扩展配方结构或引入注册表。背包配方列表由三行扩为五行，继续使用固定数组和固定容量 GPU 缓冲。

## 6. 协议与客户端镜像

协议唯一支持版本升级为 v8：

- `PlayerInput` 追加一个固定长度的采掘布尔值；
- `PlayerState` 追加活动标记、目标位置、已完成 tick、总 tick 和可掉落标记；
- 非活动状态的新增字段必须全部为零；活动状态必须满足 `1 <= progress < required`；
- 原 `BreakBlock` packet ID `1` 保留为空洞，不分配给其他消息；v8 收到该 ID 按协议违规关闭连接；
- 其余既有 packet ID 保持不变；v7 或其他版本在进入 Play 前稳定拒绝，不协商、不降级。

客户端不预测采掘完成，不提前删除方块，也不修改物品。HUD 直接读取最后一份有效 `PlayerState`；reset、断线和新登录清空旧状态。

## 7. 图形与输入

游戏输入路由把主键从上升沿动作改为按住状态，并随固定步传入预测器。背包和熔炉界面中的点击仍保持上升沿；容器打开时发送非采掘输入，使服务端在下一权威 tick 清零。

采掘条复用现有 hotbar HUD pipeline，只增加背景和填充两个 quad。填充宽度为 `progress / required`，颜色由可掉落标记选择绿色或橙色；不新增纹理、glyph、shader、pipeline 或动态分配。背包五行配方继续复用现有命中测试几何和物品色块。

## 8. 存档、迁移与回退

玩家 schema 保持 v3。工具沿用现有 `ItemID + Count` 字段，不增加耐久或其他负载；区块 schema 保持 v4，在途采掘不保存，重启后自然清零。新程序可以直接读取全部旧存档。

旧程序遇到包含新工具 ID 的玩家文件时会按未知物品稳定拒绝且不得覆盖。升级前仍需正常关服并备份世界目录；若要回退到旧程序，必须恢复首次保存工具物品之前的备份。

本批不改变世界种子、矿石规则或已有区块内容。

## 9. 失败与原子性

松键、无命中、超距、区块未就绪或目标变化是正常取消，只发布清零状态，不逐 tick 发送拒绝消息。非有限视角继续按现有输入规则拒绝，并把移动和采掘意图恢复为安全零值。

普通方块在错误工具下不预留方块掉落；熔炉则只为内部非空物品预检批量掉落容量。容量不足时方块、熔炉状态、内部物品、掉落物和区块 revision 均保持不变，完成请求拒绝一次并清零。继续按住会从头开始新一轮采掘。

所有采掘状态只由 simulation owner 写入；跨 goroutine 仍只传递不可变输入和发布消息。

## 10. 性能与 benchmark

每 tick 最多增加八次六格 DDA 射线和固定次数的数组/标量访问。采掘推进需要零堆分配，并用单元测试或微基准锁定；不得为该功能增加 per-player goroutine、动态目标表或无界队列。

协议载荷和权威 tick 工作量已经改变，benchmark 报告场景升级为 v10。`cmd/perfcheck` 默认拒绝 v9/v10 混比，只在显式 `--allow-scenario-upgrade 9:10` 时执行完整性和绝对门禁并跳过相对回归。M2 基线保持原路径和内容；M5 在冻结候选提交上通过现有无窗口路径生成一次 Memory 报告，通过后再生成一次 TCP 报告，任一步失败立即停止且不得重跑。两步均通过后才用 Memory 精确字节更新 M5 v10 基线。

## 11. 验证范围

- `internal/core`：稳定 ID、工具单格上限、两条配方、背包添加与同类合并边界。
- `internal/network`：v8 codec golden、packet 注册、非法状态、旧版本拒绝、small-packet fuzz 与 benchmark。
- `internal/sim`：全部方块/工具组合、计时、中断、目标和工具切换、错误工具无掉落、裸手启动、熔炉内容保全、容量失败及多人确定顺序。
- `internal/server`：Memory/TCP 登录与持续采掘闭环、慢客户端隔离和最终权威状态。
- `internal/client`、`internal/render`、`cmd/mcgo`：按住输入、容器抑制、reset、五行配方、固定缓冲容量和双色进度条。
- `cmd/perfcheck`：v9→v10 显式迁移、同场景回归与跨 transport 门禁。

每组遵循 red-green-refactor，并在验证通过后独立提交。收尾执行受影响包 race、全仓 `go test ./... -race`、`go vet ./...`、架构测试、`gofmt -l .`、OpenSpec strict、协议 fuzz/benchmark、采掘微基准和 scenario v10 一次性性能链。所有自动验证不得启动或聚焦前台游戏窗口。
