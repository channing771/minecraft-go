# 常见块状材料与无缝草地设计

## 1. 背景

当前项目只有 12 个稳定方块 ID。已有石头、泥土、草方块、基岩、石砖、煤矿、铁矿、熔炉、铁块和箱子等内容，但缺少常见建筑材料，大片建筑与地形的视觉重复度较高。

现有方块使用确定性的 16×16 程序化材质和 2D array atlas。贪心网格按材质、AO 和天空光拆分四边形，而 terrain shader 为每个四边形重新从 `(0,0)` 计算 UV。相同草材质一旦被 AO、光照、区段或区块边界拆开，纹理相位就会重置；草侧缘本身也没有保证左右边界可平铺，因此多个草方块相邻时会出现可见断层。

本设计先完成标准立方体材料，不同时引入方向状态或非完整方块几何。

## 2. 目标与非目标

### 2.1 目标

- 新增 14 种可堆叠、可放置、可挖掘并掉落自身的常见块状材料。
- 保持独立游戏的自然像素写实风格，不使用 Mojang 或其他未经授权的美术资源。
- 从共享渲染路径修复草方块跨四边形、区段和区块的纹理相位断层。
- 用单一 cutout 路径呈现可信的玻璃和树叶，不新增透明排序或第二个 terrain pass。
- 让新玩家直接获得材料包，同时不修改已有玩家的背包。
- 保持客户端/服务端权威边界、固定图集、固定实例格式和预热后零分配热路径。

### 2.2 非目标

- 不把新材料加入世界生成或配方。
- 不实现沙子/砾石重力、树叶腐烂、雪融化或玻璃破碎损失。
- 不实现横向原木、薄雪层或其他方块状态。
- 不实现真半透明、透明排序、反射、法线图、PBR、动画材质或外部 bitmap 资产。
- 不增加新的工具类型、渲染框架或通用数据驱动材质系统。

## 3. 固定材料清单

方块和对应物品只追加在现有稳定编号末尾，顺序固定为：

1. `CobblestoneID` / `ItemCobblestone`：圆石；
2. `SmoothStoneID` / `ItemSmoothStone`：平滑石；
3. `SandID` / `ItemSand`：沙子；
4. `GravelID` / `ItemGravel`：砾石；
5. `OakLogID` / `ItemOakLog`：固定竖向原木；
6. `OakPlanksID` / `ItemOakPlanks`：木板；
7. `LeavesID` / `ItemLeaves`：树叶；
8. `GlassID` / `ItemGlass`：玻璃；
9. `BrickID` / `ItemBrick`：砖块；
10. `WhiteWoolID` / `ItemWhiteWool`：白色羊毛；
11. `RoofTileID` / `ItemRoofTile`：红色瓦块；
12. `ClayID` / `ItemClay`：黏土；
13. `SnowBlockID` / `ItemSnowBlock`：完整雪块；
14. `MossyCobblestoneID` / `ItemMossyCobblestone`：苔藓圆石。

`BlockID` 紧随 `ChestID`，`ItemID` 紧随 `ItemChest`。编号一旦提交不得重排或复用。

## 4. 架构决策

### 4.1 继续扩展现有注册与 switch

`core` 增加 `RegisteredBlock`，作为方块编号合法性的唯一基础判断；现有 `RegisteredItem`、`ItemPlacement`、`BlockDrop` 和 `ItemStackLimit` 继续承担物品规则。`network` 与 `storage` 在信任边界调用这些判断，未知编号直接拒绝，不再由 `assets.Registry.Material` 默认显示成石头。

本批不建立新的通用 `BlockDefinition` 框架。14 个固定材料虽然会增加现有 switch 的分支，但当前没有方块状态、脚本化行为或运行时扩展需求；引入跨包描述表会扩大依赖与迁移面，却不会改善本批的可观察结果。

### 4.2 分离“可绘制面”和“不透明遮挡”

当前 `mesh.Registry.Opaque` 同时承担三个含义：方块自身是否产生面、邻居是否遮住该面、以及是否参与 AO/天空光遮挡。玻璃和树叶需要“自身可见但不完全遮挡”，因此必须拆开。

保留 `Opaque(id)` 只表示 AO 与天空光遮挡。网格增加按当前方块和相邻方块共同判断的面可见性：

- 空气或未注册方块不产生面；
- 相邻完全不透明方块遮住当前面；
- 相同的玻璃之间、相同的树叶之间不生成内部面；
- 不透明方块与 cutout 方块相邻时保留不透明方块的面，使观察者能透过孔洞看到它；
- 两种不同 cutout 方块相接时不生成共面内部表面，避免重叠深度面闪烁。

玻璃和树叶仍使用标准完整方块碰撞；其透明语义只影响网格、AO 和天空光。

### 4.3 世界坐标 UV

terrain shader 已能从区段 origin 与 quad 局部顶点得到世界坐标。材质 UV 改为直接取当前面的两个世界空间轴，不新增 quad 字段、不修改 8 字节实例格式。

因此，同一材质即使被 AO、天空光、贪心合并上限、区段或区块边界拆成多个 quad，采样相位仍由同一世界坐标决定。负坐标继续依赖 atlas sampler 的 repeat 地址模式。

该改动会统一影响全部 terrain 材质，现有视觉 golden 必须按同一提交重新生成并审查。

### 4.4 单 pass alpha cutout

全部材质仍上传到同一 2D array atlas。树叶与玻璃的基础层只生成 alpha `0` 或 `255`；fragment shader 在采样 alpha 低于固定阈值时 `discard`，其余像素按不透明颜色写入现有深度目标。

cutout mipmap 在初始化时使用保持覆盖率的降采样规则，防止玻璃边框和树叶簇在远处整体消失；这一处理不进入每帧热路径。其他完全不透明层保持现有颜色平均语义。

本方案不提供颜色叠加或半透明层次。它以少量像素边框、高光和孔洞表达玻璃，以不规则孔洞表达树叶，避免透明排序和第二个 render pass。

## 5. 程序化材质规则

全部材质继续为确定性的 16×16 RGBA，注册表构造时只生成一次：

- 圆石：不规则石块轮廓与深色缝隙；
- 平滑石：低对比的大块矿物斑纹，不使用明显砖缝；
- 沙子：浅金色细颗粒与少量成簇亮点；
- 砾石：深浅灰混合的多尺寸碎石；
- 原木：四个侧面为纵向树皮，顶面和底面为同一组年轮；
- 木板：暖色错缝木板、细暗缝与少量结疤；
- 树叶：成簇深浅绿色，约三成基础像素透明；
- 玻璃：透明中心、像素边框和少量对角高光；
- 砖块：红褐色错缝砖与低饱和灰缝；
- 白色羊毛：暖白底色与低对比纤维簇；
- 红色瓦块：重叠横排的红褐瓦纹；
- 黏土：冷灰蓝细密斑块；
- 雪块：亮白顶面与略偏冷蓝的侧面；
- 苔藓圆石：复用圆石结构，叠加不规则绿色苔斑。

草顶面的明暗草簇采用跨边界包裹绘制。草侧缘高度按闭合的周期序列生成，纹理最右列到最左列的草缘高度变化不得超过一个像素；成簇图案跨边界时从另一侧继续，而不是在边缘截断。

视觉目标是“自然像素写实”：保持清晰像素边界和材料辨识度，不使用高对比逐格轮廓，也不使用会在 16×16 下显糊的连续渐变。

## 6. 游戏规则与新玩家材料包

每种新物品的单格上限为 64，放置后写入对应方块。一次可采收的挖掘完成后掉落自身，包括玻璃；这是为了让展示型建筑材料可回收，不模拟现实玻璃损耗。

采掘规则固定为：

- 沙子、砾石、树叶、玻璃、白色羊毛、黏土、雪块需要 5 tick，手持任意物品都可采收；
- 原木、木板需要 15 tick，手持任意物品都可采收；
- 圆石、平滑石、砖块、红色瓦块、苔藓圆石复用 `StoneID` 规则：空手或损坏工具为 30 tick 且可采收，石镐为 15 tick，铁镐为 8 tick，手持其他普通物品为 30 tick 但不可采收。

不增加工具种类或高于石头的工具门槛。服务端仍是放置、挖掘、掉落和背包状态的唯一权威。

当 `PlayerStore.LoadPlayer` 返回 `ErrPlayerNotFound` 时，`newMissingCachedPlayer` 在 27 格背包的前 14 格依清单顺序各放入 64 个新材料，快捷栏保持为空。材料包只属于“缺失玩家”初始快照：

- 已存在玩家恢复原存档，不补发；
- 同一新玩家确认登录并保存后不再补发；
- 登录在确认前中断时不落盘，下次仍按缺失玩家重新准备，不会累加；
- 非法材料包构造视为开发错误，由现有 inventory validity 检查拒绝。

## 7. 协议与存档兼容性

### 7.1 协议 v14

线上字节布局不变，但合法方块和物品编号集合扩大，因此协议从 v13 升为 v14。旧客户端在 handshake 阶段收到明确的版本不匹配，不会进入 Play 后才因未知物品断开。Memory 与 TCP 继续使用同一版本、codec 和消息校验。

### 7.2 玩家 schema v6

玩家 schema 从 v5 升为 v6，编码布局不变。v5→v6 migration 为 identity migration，只更新语义版本并保留完整背包、耐久、位置和生命值。它不得向已有玩家注入材料包。

### 7.3 区块 schema v7

区块 schema 从 v6 升为 v7，编码布局不变。v6→v7 migration 保留 palette、掉落物、熔炉、箱子和 revision，只更新语义版本。新材料方块可直接使用既有稳定 `uint16` palette 表达。

旧 schema 数据可被新版本无损读取并按现有 `NeedsRewrite`/迁移机制重写。新 schema 对旧程序是 future schema，旧程序必须明确拒绝，不能把新编号默认为石头、空气或损坏的旧数据。

## 8. 视觉验证

在现有无窗口 `captureScenes` 列表末尾追加 `materials-showcase`，不创建或聚焦前台窗口。场景使用固定正午、固定相机和通过正常镜像/mesher/renderer 路径装入的确定性夹具，至少包含：

- 14 种新材料各一个近景样本及一段多方块表面；
- 八格连续草地，同时经过至少一个 AO 或天空光拆分边界；
- 两个相邻玻璃方块，证明内部面被剔除且后方方块可见；
- 两个相邻树叶方块，证明孔洞、光照和内部面行为；
- 原木顶面年轮与侧面树皮同时入镜。

世界坐标 UV 会改变共享地形背景，因此执行完整无窗口抓帧；只提交实际变化的 golden，但所有场景都必须逐张查看。视觉差异继续使用现有双阈值，不因本变更放宽。

## 9. 测试与验证

### 9.1 自动化覆盖

- `core`：追加 ID、`RegisteredBlock`、物品注册、堆叠、放置和掉落映射；
- `assets`：14 种材质的确定性、完整尺寸、结构差异、分面映射、草边缘可平铺、cutout alpha 与 mip 覆盖；
- `mesh/render`：世界坐标 UV 跨 quad/区段/区块连续，cutout 方块自身可见，同类内部面剔除，不透明邻面保留，AO/天空光不遮挡，shader 正确丢弃透明像素；
- `server`：缺失玩家只获得一次材料包，旧玩家不变，登录中断不持久化重复材料；
- `network`：协议 v14 golden/fuzz、新 ID 经 Memory/TCP 往返一致、旧版本握手拒绝；
- `storage`：玩家 v5→v6、区块 v6→v7、新材料 round-trip、future schema 拒绝；
- `cmd/mcgo`：`materials-showcase` 夹具、收敛和无窗口图像产出。

### 9.2 性能记录

性能只记录，不作为数值门禁。记录修改前后的 terrain mesh benchmark、quad 数和上传量；继续守住实例格式不变、固定 atlas、固定容量、无每帧分配和无第二个 pass。真实 overflow、数据丢失、I/O 错误或报告结构错误仍失败。

### 9.3 收尾命令

按风险执行受影响包 race 测试、`go test ./internal/archcheck -count=1`、`go test ./... -race`、`go vet ./...`、`gofmt -l .`、`git diff --check` 与 `openspec validate --all --strict --no-interactive`。渲染验证只走无窗口路径。

## 10. 风险与缓解

- **世界坐标 UV 改变现有纹理相位**：完整抓取并查看全部视觉场景，不只更新 `materials-showcase`。
- **cutout 增加可见面与 overdraw**：同类内部面剔除，记录 mesh/quad/upload 指标；不增加 pass 或透明排序。
- **cutout mip 导致远处孔洞消失或膨胀**：以固定覆盖率测试和无窗口远景样本锁定有界行为。
- **大量新增 ID 漏接某条映射**：以清单驱动的注册、放置、掉落、存档和协议表格测试锁定一一对应。
- **材料包污染旧玩家**：只在 `ErrPlayerNotFound` 分支构造，迁移测试明确断言旧背包不变。

## 11. 被否决的替代方案

### 11.1 只修改纹理

只让纹理左右边缘接近不能修复 AO、天空光或网格边界造成的 UV 相位重置，也无法让玻璃和树叶真实镂空，因此否决。

### 11.2 真半透明 terrain pass

真半透明玻璃需要混合、排序、深度策略和额外 pass，会显著扩大渲染与性能验证范围。cutout 已能表达透明中心、边框和高光，因此本批否决。

### 11.3 通用材质描述系统

建立跨包数据表、注册 DSL 或插件式材质系统是没有当前消费者的抽象。现有注册表与稳定 switch 足以承载固定清单，因此本批否决。

### 11.4 同时实现方块状态

横向原木与薄雪层需要方向、高度、碰撞、选取、协议和存档状态编码，是独立闭环。把它们与 14 种材质和草地修复捆绑会失去可评审性，因此延期为后续 change。

## 12. 交付顺序

1. 建立 OpenSpec change，冻结材料清单、兼容性和视觉验收场景。
2. 追加稳定 ID、注册规则、协议/存档版本与 migration，并完成新玩家材料包。
3. 分离面可见性与遮挡语义，实现世界坐标 UV 和单 pass cutout。
4. 实现 14 种材质与草地可平铺生成规则。
5. 追加 `materials-showcase`，更新并人工复核受影响的无窗口 golden。
6. 完成性能记录、全仓验证、主规格同步与归档。
